# E2E 브라우저 검증 (삭제 금지)

실제 크로미움을 띄워 **화면을 클릭·입력해** 기브싸인가 깨졌는지 확인하는 스크립트입니다.
`tests/*.test.ts`(Vitest)는 서버 로직만 봅니다. 여기가 없으면 **화면이 깨졌는지 확인할 방법이 사라집니다.**

## 2026-08-31 제품 전환 안내 (읽고 시작하세요)

기브싸인가 문자후원·충전(문자PG) 서비스로 전환되면서 **오버레이 · TTS · 유튜브 연동 화면이 삭제**되었고,
정산이 **사회복지기관 출금 요청 → 지정 지급일 자동 지급**으로 바뀌었습니다.

### 새 기준 스크립트

- `pg-e2e.mjs` — **현재 제품 기준으로 새로 쓴 스크립트입니다.**
  자동 정산(지급 내역 탭 · 지급 주기 D+N), 포인트 지급 처리, 연동 API 키 발급·폐기,
  상품 설정(비실물·실물·배송정책), MO 안내문자, 주문·배송,
  관리자 자동 지급 현황과 상품·주문 모니터링, 수수료 정책의 지급일 일괄/개별 지정,
  약관 문안을 확인합니다.

### 아직 재작성이 필요한 스크립트

사라진 화면을 검증하는 구간이 남아 있어 **기본 실행 대상에서 제외**했습니다. 이름을 직접 주면 돌아갑니다.

- `round10-e2e.mjs`, `studio-e2e.mjs` : 오버레이 · 유튜브 · TTS 구간
- `round5-e2e.mjs`, `round6-e2e.mjs`, `admin-e2e.mjs`, `gap-e2e.mjs` : 일부 구간

용어(후원 → 결제)는 일괄 정리했지만, **화면 구조가 바뀐 구간은 실제로 앱을 띄워 보며 다시 써야 합니다.**
스크립트를 지우지 말고, 실패하는 구간부터 하나씩 새 화면 기준으로 고쳐 주세요.

## 실행 방법

```bash
# 1) 터미널 A — 앱 실행
npm run dev

# 2) 터미널 B — 전체 검증 (스크립트마다 DB 초기화·재시드)
npm run test:e2e

# 일부만
npm run test:e2e -- pg admin

# 기본에서 뺀 옛 스크립트를 굳이 돌릴 때
npm run test:e2e -- round10 studio

# 재시드 없이 (빠르지만 실행 순서에 따라 결과가 달라질 수 있음)
npm run test:e2e -- --no-reseed
```

처음이라면 브라우저를 한 번 받아야 합니다.

```bash
npx playwright install chromium
```

사전 설치된 크로미움을 쓰는 환경(컨테이너 등)은 경로를 넘기면 됩니다.

```bash
E2E_CHROMIUM=/opt/pw-browsers/chromium npm run test:e2e
```

다른 주소로 띄웠다면 `E2E_BASE=http://localhost:3000` 처럼 지정합니다.

## 구성

| 스크립트 | 무엇을 지키는가 |
|---|---|
| `round5-e2e.mjs` | 스튜디오 셸·사이드바 정보구조, 메뉴 10종 실제 진입, 모바일 햄버거 |
| `round6-e2e.mjs` | 결제 페이지 PC/모바일 분기 + **PC 웹 결제 PIN 인증 전 구간**(금액·메시지 → 번호 → PIN 링크 문자 → PIN 입력 → 완료 → 최근 결제 노출) |
| `round7-e2e.mjs` | 고객센터 문의 접수·게스트 스레드 승계, 최고관리자 문의 검색/필터/답변, 로그인 CSRF, `/api/health` 축소 |
| `round8-e2e.mjs` | 정산 탭 4종, **원천징수 미리보기(소득세 3% + 지방소득세 10% + 소액부징수)**, 주민등록번호 수집, 정산 계좌, 금칙어 추가/중지/삭제 |
| `round9-e2e.mjs` | 지급대행·원천징수 CSV 권한(401/403/400), 배치번호 가드, 관리자 권한 5종, 개인정보 표시 원칙 |
| `round10-e2e.mjs` | 알림 버튼(PC 우측 상단·모바일 햄버거 왼쪽), **정산 요청 → 최고관리자 알림함 도착**, 영업일 5일 정산주기 안내·캘린더 범례, 공휴일 등록/삭제, 오버레이 SSE·테스트 결제 표시 |
| `gap-e2e.mjs` | 기기별 안내 문구가 서로 새지 않는지, 모의(mock) 고지, 공개 페이지 스모크 |
| `studio-e2e.mjs` | 유튜브 mock OAuth 연결·해제·재연결·거부, 오버레이 URL 발급·설정 저장, 스트림 키, 결제 설정·프로필 저장 |
| `admin-e2e.mjs` | 관리자 28개 화면 전수 스모크, 한도 정책 15개 필드와 정책 등록 |

`_helpers.mjs` 는 공통 로그인·리포터·모의 발송함 조회를 담습니다.

## 결과 읽는 법

각 줄이 `PASS | 검사 이름` 또는 `FAIL | 검사 이름 | 사유` 로 나오고, 끝에 요약이 붙습니다.
하나라도 실패하면 종료코드가 1 이라 CI 에서도 그대로 쓸 수 있습니다.

## 주의

- **시드 데이터에 의존합니다.** 계정·코드·MO 번호는 `_helpers.mjs` 의 `SEED` 에 모아 두었습니다.
  시드를 바꾸면 그 상수만 고치면 됩니다.
- `mock` 어댑터 기준입니다. 실제 헥토/엠투넷 연동 후에는 결제·문자 구간을 연동 규격에 맞게 다시 손봐야 합니다.
- 개발 서버(dev)는 첫 진입마다 컴파일이 끼어들어 느립니다. 전체 실행에 10~20분 걸릴 수 있습니다.
