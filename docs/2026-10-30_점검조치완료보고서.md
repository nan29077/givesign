## 설계 결정과 이유

- **정기후원 결과 미확인(PENDING)**: 멱등키를 지우지 않고 다음 배치가 결제사 조회로 먼저 확정한다. 재시도로 두 번 출금되는 것보다 하루 늦게 확정되는 쪽이 안전하다.
- **공익법인 지정 관리자 확인**: 기관의 자기 신고만으로 세법상 효력이 있는 영수증을 내보낼 수 없다. 확인은 정산 권한 관리자만, 지정 정보·고유번호·기부금 코드가 바뀌면 재확인.
- **명세 CSV 관문**: 주민번호 원문이 든 파일이라 "링크 클릭"으로 나가면 안 된다. 세션 탈취·자리 비움에 대비해 비밀번호 재확인과 사유를 받고, 토큰은 5분·1회·하루 5번.
- **pointStatus 기본 SKIPPED**: 후원에는 기관이 지급할 것이 없다. 메시지페이의 지급 상태 기계는 FEATURE_GOODS 를 켠 기관의 디지털 상품에만 산다.
- **약관 재동의 위치**: 가입 화면이 아니라 후원 확정 화면(/r/[token])이다. 이미 가입한 후원자가 다음 후원 때 반드시 지나는 곳이고, 동의 없이 결제되는 일이 없다.
- **마이그레이션 기준선**: 운영 DB 가 없어 `97e5d88` 시점 체크섬을 기준선으로 확정했다. 이후 SQL 은 주석도 손대지 않는다.
- **후원페이지 미공개 기관**: 막다른 안내 대신 /c 간편 후원 화면으로 보낸다. 승인된 기관이면 후원은 받을 수 있어야 한다.

## 남은 한계 (코드로 해결할 수 없는 것)

1. **본인인증(실명 확인) 미계약** — 영수증 정보의 성명과 주민번호가 일치하는지 확인하지 못한다. 중복 주민번호 차단과 변경 횟수 제한으로만 막는다. 계약 후 `upsertReceiptProfile` 에 실명 확인 호출을 추가한다.
2. **약관 법무 검토** — 3.0 문안은 서비스 구조에 맞게 쓴 초안이다. 검토 뒤 관리자 > 약관 관리에서 새 버전으로 교체하면 재동의가 자동으로 걸린다.
3. **구 즉시결제 경로(ALLOW_LEGACY_WEB_INSTANT_PAY)** — 되돌림 전용 플래그라 캠페인·익명을 받지 않는다. 플래그를 켤 일이 생기면 그때 확장한다.
4. **저장소 공개 여부** — `nan29077/givesign` 은 공개 저장소다. 비밀값은 없지만 결제·개인정보 처리 코드 전체가 공개돼 있어 비공개 전환을 권장한다. 단, PC 작업 폴더가 지금은 인증 없이 `git pull` 하므로 비공개로 바꾸면 PC 에 GitHub 인증(토큰 또는 SSH)을 먼저 넣어야 한다.
