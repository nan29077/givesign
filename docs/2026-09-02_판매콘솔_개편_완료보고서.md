## 1. 결정한 사항

보고서 7장에서 여쭤본 5가지를 다음과 같이 정하고 진행했습니다.

| 질문 | 결정 | 이유 |
|---|---|---|
| 옵션 구조화 범위 | **단독형** — 옵션값별 추가금 + 품절 플래그. 값별 *수량* 재고는 두지 않음 | 값별 수량 재고는 결제 승인 트랜잭션 안에서 JSON 숫자를 깎아야 하는데, 그 경로가 이중결제 방어(멱등성 4중)와 얽혀 있어 위험합니다. 재고는 상품 단위로 유지하고 "이 색상만 품절" 은 플래그로 해결했습니다 |
| 사회복지기관 환불 권한 | **요청만** 생성, 관리자 승인 | 환불은 결제사 취소 + 정산 원장 반대분개가 함께 일어납니다. 사회복지기관이 직접 실행하면 원장이 어긋납니다 |
| 상세 설명 | textarea 유지, 300자 → **2,000자** + 추가 이미지 5장 | HTML 에디터는 XSS·업로드 정책 범위가 커집니다. 이미지로 상세를 대신할 수 있게 갤러리를 넣었습니다 |
| 메뉴명 | **후원 처리** | 요청하신 표현 |
| 비실물 4번째 유형 | **`CONTENT` enum 추가** | 화면 문구만 바꾸면 지급 방식·청약철회 안내를 유형별로 다르게 강제할 수 없습니다 |

## 2. 기능 결함 수정 (A그룹)

### A-1. 배송지 원문 자동 복호화 제거

가장 위험했던 항목입니다.

- 목록은 이제 `receiverMasked` / `phoneMasked` / `addressMasked` 만 그립니다 (`홍*동 / 010-****-1234 / 서울 강남구 ***`).
- `[주소 보기]` 를 눌러야 원문이 열리고, 그 순간 감사로그 `SHIPMENT_ADDRESS_VIEW` 가 남습니다 (거래번호 · 사회복지기관 · IP · UA).
- 주문서 CSV 내려받기에는 원문이 들어갑니다(택배 발주에 필요). 대신 내려받을 때마다 `SHIPMENT_EXPORT` 로 기록합니다.
- 신규 파일: `src/components/studio/address-reveal.tsx`, 액션 `revealShipmentAddressAction`

### A-2. 실물 주문이 지급 대기에 섞이던 문제

- 금액 확정 시점(`charge-select.ts`)에서 실물이면 `pointStatus = SKIPPED` 로 정합니다.
- 마이그레이션에서 이미 쌓인 실물 주문의 `PENDING` 도 일괄 `SKIPPED` 로 정리했습니다.
- 파트너 API `GET /charges?status=pending` 에도 더 이상 실물이 나오지 않습니다.

### A-3. 상품 이미지가 구매자에게 안 보이던 문제

- `/r/[token]` 선택 화면에 대표 이미지 썸네일(목록) + 큰 이미지 + 추가 이미지 가로 스크롤을 렌더합니다.
- 수정 폼에도 이미지 칸을 넣었습니다(등록 후 교체 가능). 비실물에도 넣었습니다.
- 안내 문구가 사실과 맞게 됐습니다.

### A-4. 결제 상세에 주문 정보 추가

상품명 · 종류 · SKU · 수량 · 옵션 · 상품금액 · 배송비 · 배송상태 · 배송지(마스킹+보기) · 송장 · 발송/완료 시각. 주문 카드에서 거래번호를 눌렀을 때 정보가 줄어들던 문제가 없어졌습니다.

### A-5. 상품 보관 복원

`restoreChargeProductAction` + `보관함` 탭. 되살리면 **숨김 상태**로 돌아옵니다(값 확인 후 직접 노출).

### A-6. 잔재 정리

- 결제 설정의 미사용 import 3개 제거 (ESLint 경고 해소)
- "라이브 표시를 관리합니다" 문구 제거
- 예전부터 아무도 부르지 않던 `previewSafeText` 제거

### A-7. 지급 상태 용어 통일

`pointStatusLabel` 신설 — 화면·CSV 모두 **지급 대기 / 지급 완료 / 지급 보류 / 지급 대상 아님**. 예전에는 화면은 "지급 대기", 엑셀은 "대기" 였습니다.

## 3. 후원 항목 관리 개편 (B그룹)

### 목록과 폼을 분리

```
/studio/products                    목록 (실물 / 비실물(컨텐츠) / 보관함)
/studio/products/new?kind=physical  등록
/studio/products/[id]               수정 + 미리보기
```

목록은 썸네일 · 이름 · 뱃지 · 결제금액(상품+배송비) · 판매건수와 행별 조작(위/아래 · 노출/숨김 · 복제 · 보관)만 보여 줍니다. 저장 버튼이 상품 수만큼 생기던 구조를 없앴습니다.

### 실물 등록 폼 — 7개 섹션

| 섹션 | 내용 | 신규 |
|---|---|---|
| 1 기본 정보 | 상품명 · SKU · 노출 여부 | |
| 2 판매 정보 | 판매가 · **과세/면세** · 재고 · 재고 경고 · 1회 최대 수량 | 과세구분 |
| 3 옵션 | 옵션 편집기 — 값별 **추가금** · **품절** | 전면 신규 |
| 4 이미지 | 대표 + **추가 이미지 5장** | 갤러리 |
| 5 상세 설명 | 2,000자 | 확대 |
| 6 배송·반품 | 배송비 · 조건부무료 · **출고 소요일** · **반품/교환 배송비** | 3개 신규 |
| 7 상품정보 제공 고시 | 6개 품목별 필수 항목 자동 구성 | 전면 신규 |

우측에 **후원자에게 보이는 모습 미리보기**를 고정으로 붙였습니다. 결제 한도 통과 여부, 옵션 최대 선택 시 금액, 고시 미작성 항목을 그 자리에서 경고합니다.

### 비실물(컨텐츠) 등록 폼

- 유형 4종: 포인트 / 상품권 / 이용권 / **컨텐츠**
- **지급 방식** 3종:
  - `사회복지기관 수동 지급` — 후원 처리에서 직접 처리
  - `연동 API 자동 지급` — 사회복지기관 서버가 가져가 적립
  - `결제 즉시 문자 발급` — 결제 완료 순간 코드·링크를 문자로 발송 (신규 구현)
- **청약철회 제한 안내** — 컨텐츠 유형은 필수 입력

즉시 발급은 결제 성공 직후 `deliverInstantFulfillment` 가 처리합니다. **문자 발송이 실패해도 결제를 되돌리지 않고** `pointStatus=FAILED` 로 남겨 사회복지기관이 다시 처리하게 합니다(원칙 3 준수).

### 그 밖

- 상품 복제 (`(2)`, `(3)` 자동 번호, 복제본은 숨김)
- 위/아래 버튼 정렬 — 저장할 때마다 0..n 으로 다시 매겨 순서 중복·구멍이 생기지 않습니다
- 12개 상한을 등록 화면 상단에 `(3/12개 사용)` 으로 미리 고지

## 4. 후원 처리 (C그룹)

### 탭 3개

```
/studio/orders?tab=delivery   실물 주문·배송
/studio/orders?tab=digital    비실물(컨텐츠) 판매
/studio/orders?tab=return     반품·교환
```

각 탭 이름 옆에 처리 대기 건수 뱃지가 붙습니다.

### 실물 주문·배송

- **통합 검색**: 거래번호 · 상품명 · SKU · 송장번호 · 받는 분(마스킹된 이름으로도 검색)
- 기간(7/30/90일/전체) · 상태 · 정렬(오래된 순 / 최신 순)
- **송장 일괄 등록** — 엑셀에서 `거래번호, 송장번호` 를 복사해 붙여넣기. 쉼표·탭·공백 모두 구분자로 인식, 최대 200줄. 처리 결과를 건별로 알려 줍니다
- **주문서 엑셀** — 22개 컬럼(상품·옵션·수량·배송지 원문·송장·반품사유까지). 택배사 발주서로 바로 씁니다
- **발송 안내 문자** — 발송으로 *처음* 바뀔 때만 1회 발송(저장할 때마다 보내지 않습니다). 체크박스로 끌 수 있습니다
- **발송 지연 경고** — 결제 후 2일 초과 미발송 건수를 통계 타일과 행 뱃지로 표시
- **환불 요청** — 각 주문에서 사유를 적어 관리자에게 올립니다

### 비실물(컨텐츠) 판매

후원 내역에 섞여 있던 지급 처리를 이쪽으로 옮겼습니다. 지급 대기/완료/보류 통계, 일괄 지급 패널, 최근 판매 30건(상품·유형·지급방식·지급시각).

### 반품·교환

`ShipmentStatus` 에 5개 상태를 추가했습니다: 반품 접수 / 회수중 / 반품 완료 / 교환 접수 / 교환 발송. 반품 상태로 바꾸려면 **사유가 필수**입니다(분쟁 근거). 회수 송장번호도 따로 받습니다.

## 5. 후원 설정 (D그룹)

`결제 설정` → **`후원 설정`**, 7탭 → 6탭.

| 탭 | 변경 |
|---|---|
| 결제·금액 | 중복되던 상품 목록 제거(개수 요약 + 이동 버튼만). **직접 입력 자체 범위·배수 단위** 추가 |
| 배송 정책 | 상품 설정에서 **이동**. 출고 소요일 · 반품/교환 배송비 · **반품지 주소** 추가 |
| 안내 문자 | MO 안내 + 감사 문자를 한 탭에 섹션 2개로 **통합** |
| 결제페이지 | 배너에 **"자동" 선택지** 추가, 실제 페이지 열기 버튼 |
| 연동 | **IP 허용목록**, **최근 호출 기록 20건**, 규격서 화면 |
| 수신·결제 방식 | 문자번호 + 결제 모드를 **한 탭으로 통합**(둘 다 읽기 전용) |

### 안내 문자 개선

- **내 번호로 테스트 발송** — 계정에 등록된 번호로만 보냅니다(임의 번호 금지)
- **치환 후 실제 길이 표시** — `LMS · 132byte` 처럼. 90byte 를 넘으면 LMS 로 나가 발송 단가가 달라지는데, 예전에는 저장 시 템플릿 원문 길이만 봤습니다

### 연동 API 개선

- 키별 **IP 허용목록**(IPv4 · CIDR). `authenticatePartner` 에서 검증하고 `IP_NOT_ALLOWED` 로 거절합니다. 비우면 제한 없음(기존 연동을 끊지 않습니다)
- **호출 기록** — 인증 실패(401/403/429), 요청 오류(400/404), 쓰기 성공을 남깁니다. 응답 본문은 남기지 않습니다. 조회 API 의 성공은 폴링이라 남기지 않습니다
- 실패 응답에도 사회복지기관을 붙일 수 있도록 `PartnerAuthFail` 에 `merchantId`/`keyId` 를 추가했습니다. 이게 없으면 "키는 맞는데 401" 인 경우가 로그에 안 남습니다
- 규격서를 `/studio/docs/partner-api` 에서 바로 봅니다(파일 경로 노출 제거)
- `POST /charges/shipment` 를 규격 안내에 추가(이미 있던 엔드포인트인데 화면에 없었습니다)

**데이터 정정**: 이미 쌓인 실물 주문의 `point_status = PENDING` → `SKIPPED`

**옵션 JSON 형식 변경**: `[{name, values:["S","M"]}]` → `[{name, values:[{label,addPrice,soldOut}]}]`. **구 형식도 그대로 읽습니다**(`parseOptions` 가 둘 다 받음). 기존 상품 데이터를 건드리지 않아도 됩니다.

**시드 버전 9 → 10**: 새 옵션 형식, 컨텐츠 상품(즉시 발급), 고시정보, 반품 정책 포함. 미리보기 DB(`.pglite`)는 `도구_미리보기초기화.bat` 으로 새로 만들어야 반영됩니다.

## 8. 하지 않은 것 / 남은 것

정직하게 적습니다.

| 항목 | 이유 |
|---|---|
| 옵션값별 **수량** 재고 | 결제 승인 트랜잭션에서 JSON 숫자를 깎아야 하는데 이중결제 방어 경로와 얽혀 위험합니다. 필요하면 별도 variant 테이블로 설계해야 합니다 |
| 상세 설명 HTML 에디터 | XSS·업로드 정책 범위가 커집니다. 추가 이미지 5장으로 대신했습니다 |
| 목록 체크박스 다중 선택 후 일괄 노출/숨김 | 행별 토글로 구현했습니다. 상품이 12개 상한이라 다중 선택의 이득이 작습니다 |
| 치환자 클릭 삽입 | 치환자 목록은 보여 주지만 클릭으로 본문에 넣는 기능은 넣지 않았습니다 |
| `PublicShellClient` 의 `aside` 미사용 | **개편과 무관한 기존 결함**입니다. FAQ·로그인·마이페이지 등 10개 페이지가 사이드 콘텐츠를 넘기는데 렌더되지 않습니다. 공개 화면 레이아웃을 건드리는 일이라 이번 범위에서 뺐습니다. 지시 주시면 별도로 처리하겠습니다 |

## 9. 실행 순서

소스가 크게 바뀌었으므로 반드시 다시 빌드해야 합니다.

```
1. 3_서버종료.bat            서버 완전 종료
2. 도구_미리보기초기화.bat     .pglite + .next 삭제 (시드 버전 10 반영)
3. 1_미리보기실행.bat         재빌드 후 실행 (1~3분)
```

개발 서버(PostgreSQL)를 쓰신다면 `npm run db:reset` 으로 마이그레이션과 시드를 함께 적용해 주세요.

테스트는 Windows 에서 `도구_테스트실행.bat` 으로 확인 부탁드립니다.
