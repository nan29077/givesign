# 문서 서식 원본 편집 (2026-11-04)

기관이 가지고 있던 서식(PDF·한글·워드·스캔본)을 그대로 올리고, 기관 콘솔에서 원본 위의 글자를 직접 고칠 수 있게 했다. 고친 글자는 원래 글꼴·크기·색·방향으로 들어간다.

## 1. 흐름

```
서식 등록(파일 업로드) ─ 업로드 때 편집 바탕 PDF 생성
   PDF → 그대로 / PNG·JPG → 한 쪽 PDF / 한글·워드 → LibreOffice 가 있으면 변환(없으면 PDF 저장 안내)
        ↓ 저장하면 편집 화면으로 바로 이동
/studio/documents/[id]/edit
   글자 고치기 : 원래 글자를 누르면 그 자리에 같은 크기·색의 입력칸 → Enter 확정
   새 글 넣기  : 빈자리를 누르면 가장 가까운 글자 모양으로. 문서에 쓰인 다른 모양(글꼴·크기)으로 바꿀 수 있음
   지우기      : 글자를 누르거나 끌어서 영역을 바탕색으로 덮음
   → 고칠 때마다 서버가 실제 결과 PDF 를 만들어 다시 그림(화면 = 후원자가 받는 파일)
   → 저장: 결과 PDF 를 새 파일로 남김
        ↓
후원자 작성 화면(/doc/[token])·서명 화면(/sign/[token]) — 고친 서식을 쪽마다 그림으로 보여 주고 내려받기
서명 요청 스냅샷 — 발송 당시 결과 PDF 주소·SHA-256 고정, 완료 증명서에 서식 PDF 해시 표기
```

## 2. 글꼴을 맞추는 방법

| 순서 | 방식 | 언제 |
|---|---|---|
| 1 | 원본 글꼴 객체 그대로 | 새 글자가 모두 원본 문서에 쓰인 글자일 때(ToUnicode 를 거꾸로 읽어 원본 코드로 씀) |
| 2 | 올린 글꼴 | 기관이 같은 이름의 TTF·OTF 를 올렸을 때(예: 함초롬바탕) |
| 3 | 원본에 든 글꼴 전체 | 원본 PDF 에 부분집합이 아닌 글꼴이 들어 있을 때 |
| 4 | PDF 표준 글꼴 | Helvetica·Times 등 비내장 표준 글꼴, 라틴 글자 |
| 5 | 대체 글꼴 | 위가 모두 안 될 때. 원본 이름으로 명조/고딕·굵기를 판정해 Noto CJK KR 4종 중 선택 |

글자 크기·색·방향은 어느 경우든 원본에서 읽은 값이다. 대체 글꼴로 바뀌는 수정은 입력 중에 "원본 글꼴에 없는 글자: 앵 …" 처럼 원인 글자를 보여 주고, 오른쪽에서 그 글꼴 파일을 올리라고 안내한다.

PDF 는 보통 문서에 쓰인 글자만 글꼴에 넣는다(부분집합). 그래서 원본에 없던 글자를 쓰면 원본 글꼴로는 그릴 수 없고, 같은 글꼴 파일을 올리는 것이 정확한 방법이다.

지원 확인한 원본 형식: 한글·워드식 2바이트 CID(Identity-H), LibreOffice 1바이트 Type1(256자마다 나뉜 사전), 브라우저 인쇄 Type3, 비내장 UniKS-UCS2 한글 글꼴.

## 3. 원래 글자 지우기

덮개만 그리면 원래 글자가 복사·검색에 남는다(약정 금액 "10,000" 을 "20,000" 으로 고쳐도 숨은 10,000 이 남음). 그래서 내용 스트림을 해석해 덮개 안에 든 원래 글자를 실제로 빼고, 뒤 글자 위치는 위치 조정값으로 그대로 둔다. 폭을 모르는 글꼴·양식 XObject 안의 글자는 덮기만 하고 화면에 그 쪽을 알린다.

## 7. 운영 메모

- 한글(HWP)·워드를 서버에서 바로 바꾸려면 서버에 LibreOffice 설치 + `SOFFICE_PATH`. HWP 는 LibreOffice 에 H2Orestart 확장이 있어야 한다. 서버 변환은 서버에 설치된 글꼴로 그려지므로, 원본 글꼴을 그대로 지키려면 기관 PC 에서 PDF 로 저장해 올리는 편이 정확하다(화면에서 그렇게 안내).
- 스캔본(그림)은 글자가 그림이라 글자로 고칠 수 없다. 덮고 새로 쓰는 방식만 된다.
- 서식은 30쪽, 수정은 300곳까지.

## 8. 2차 — 등록하면서 바로 미리보고 고치기 (같은 날)

서식을 저장한 뒤 편집 화면으로 넘어가던 흐름을, **파일을 올리는 자리에서 바로 미리보고 고친 뒤 한 번에 저장**하도록 바꿨다.

| 전 | 후 |
|---|---|
| 파일 선택 → 서식 등록 → 편집 화면으로 이동 → 따로 저장 | 끌어다 놓기 → 업로드 진행률 → 같은 화면에 원본 미리보기 편집기 → [서식 등록] 한 번으로 서식·고친 결과 함께 저장 |
| 서식 이름 직접 입력 | 비어 있으면 파일 이름으로 채움 |
| 서식 화면에 "고치기" 카드와 링크 | 서식 화면 안에서 바로 편집(넓은 화면 편집은 선택) |
| 편집 화면에서만 결과 확인 | **편집(실제 결과)** · **원본과 비교**(누르고 있는 동안) · **후원자 화면**(휴대폰 폭) |
| 넣은 글 위치 고정 | 넣은 글을 끌어서 옮기기, 확대·축소(60~200%), 여러 쪽 바로 가기와 쪽별 수정 수 |
| 수정 목록 보기만 | 목록을 누르면 그 쪽으로 이동해 바로 고치기, 원본 글꼴/대체 글꼴 요약 |

안전장치
- 서식 행이 생기기 전에는 업로드 응답의 서명 토큰(기관·파일·24시간)으로 "이 기관이 방금 올린 파일" 인지 확인한다. 다른 기관 파일 주소를 넣어도 미리보기·등록이 거절된다.
- 파일을 바꾸거나 지울 때 고친 내용이 있으면 먼저 묻는다. 저장하지 않고 나가려 하면 브라우저가 묻는다.
- 서식 저장 때 기록이 저장된 것과 같으면 결과 PDF 를 다시 만들지 않는다.
- 옛 API(`/api/studio/documents/[id]/pdf-*`)는 `/api/studio/pdf-form/{preview,font}` 하나로 합쳤다.

검증: `vitest` 532건(신규 토큰·등록 전 미리보기 2건 포함) 통과, `tsc`·`eslint`·빌드 통과, `e2e/pdf-form-edit.mjs` ALL PASS(업로드 즉시 편집기·이름 자동 채움·고치기·새 글 끌어 옮기기·후원자 화면·원본 비교·등록 한 번 저장·서식 화면 이어서 고치기·넓은 화면 같은 기록).

## 9. 장애 조치 — 미리보기가 안 보임 (같은 날)

- 증상: 서식 파일을 올려도 미리보기가 열리지 않고 "원본 PDF 를 열지 못했습니다" 가 보임.
- 원인: pdf.js 6 기본 빌드가 아주 최근 브라우저에만 있는 `Map.prototype.getOrInsertComputed` 를 보완 코드 없이 쓴다. 개발 중 시험한 브라우저는 최신이라 드러나지 않았고, 그보다 이전 버전의 크롬·엣지에서는 PDF 를 여는 순간 오류가 났다. 서버(Node)는 처음부터 호환 빌드를 써서 서버 쪽은 문제가 없었다.
- 조치: 브라우저 쪽(편집기·후원자/서명자 미리보기) 모두 호환 빌드(legacy, 워커 포함)로 교체. 실패 문구를 실제 원인별로 나누고(암호·손상·네트워크·브라우저) 내려받기 대안을 함께 보여 준다.
- 재발 방지: 화면 흐름 점검(`e2e/pdf-form-edit.mjs`)을 그 기능을 끈 브라우저로 돌린다. 조치 전 같은 조건에서 미리보기 실패, 조치 후 업로드·고치기·후원자 화면·등록까지 모두 통과.
