## 3. 영역별 중간·낮음 조치 요약

### A 결제·정산 (중간 7 · 낮음 9 + 자동화에서 넘어온 2) — 전부 조치
- 승인 후 기록 실패 흡수 → UNKNOWN 보장, 정리 배치가 15분 지난 `REQUESTED/TIMEOUT` 을 대사 큐로. 금액 확정·웹 후원 경로의 PIN 발급 예외는 실패로 닫고, 30분 지난 고아도 배치가 닫음(`payment-recovery.ts`).
- 헥토 조회 빈/모르는 상태 → PENDING. 승인 응답 `UNKNOWN` 이면 조회 1회 시도. 결과 모르는 거래로 재진입하면 한도·재고를 다시 잡지 않음.
- MO 행 생성·멱등키 예외는 P2002 일 때만 중복, 그 외는 다시 던짐(EMMA 문자 소실 방지). MTONET 이 050·1588 둘 다 허용.
- 정기후원: 재개 후 지난 실패 재집계로 즉시 재정지되던 문제, 대사 취소 시 실패 문자 2통.
- 지급 크론 잠금 소유자 확인, 실결제사 PIN 성공 코드 기본값 거부, 만료 PIN 세션 즉시 정리, 웹훅 적재 리스, 웹 후원 `CONFIRM_LINK` 고정 기록.
- MO 후원 `source: 'SMS'`, 알림톡 이력 행을 발송 전에 생성.

## 5. 결정이 필요한 것 (코드로 끝낼 수 없음)

1. **메일 발송 연동** — 비밀번호 재설정 링크는 운영에서 로그에만 남고, 후원회원 이메일 소유 확인도 불가. 메일 연동(SES 등)을 붙일지, 그 전까지 `/reset-password` 의 "재설정 링크가 발송됩니다" 문구를 바꿀지.
2. **스테이징 실연동 PIN 성공 코드** — 결제사가 mock 이 아니면 `PAYMENT_PIN_SUCCESS_CODES` 를 실제 규격 값으로 넣어야 PIN 이 통과한다. 헥토 조회의 명시적 실패 코드도 규격서를 받으면 `HECTO_SPEC.inquiryStatus.failed` 보강.
3. **사업자 표시 정보** — `BUSINESS_*`(대표자·사업자등록번호·주소·연락처 등) 값. 상호만 기본값("주식회사 이십세기 소년들").
4. **배포 환경 `sharp`** — 공개 화면 이미지 최적화에 필요.
5. **이미 올린 글꼴** — 이번 조치 전에 올린 글꼴은 대장에 없어 렌더에 쓰이지 않는다. 해당 서식은 글꼴 재업로드 필요(운영 데이터 없음 전제).
6. **약정서 스냅샷의 후원자 표시 이름** — 약정 당사자 표기로 유지했다. CLAUDE.md "마스킹 값만" 규칙의 예외로 명시할지.
7. **콘텐츠 월 생성 한도 조정 기능** — 지금은 기본값 30 고정. 관리자 조정이 필요한지.
8. **배송 연락처** — `FEATURE_GOODS` 를 다시 켜면 배송지 열람의 전화번호도 마스킹 값만 나온다. 택배 발송에 원문이 필요하면 별도 관문(비밀번호 재확인 등) 설계 필요.
9. **LibreOffice 변환 격리** — 네트워크 차단 컨테이너·워커 분리는 운영 인프라 작업(`docs/2026-11-05_점검_D_조치.md`).
