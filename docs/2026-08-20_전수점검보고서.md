# 기브싸인 전수 점검 보고서 (2026-08-20)

점검 범위: 전체 소스 코드(서버 액션·서비스·화면), 4개 역할(비로그인·후원자·사회복지기관·통합 관리자)의 전 페이지 56곳 실제 브라우저 탐색, 대시보드 시각 검토.

점검 방법: (1) 코드 정적 리뷰 2회(서버 정합성·보안 / 화면·UX), (2) Playwright 로 전 페이지 방문하며 HTTP 오류·콘솔 오류·렌더 오류·가로 오버플로·브랜드 잔존 자동 감지, (3) 주요 화면 스크린샷 시각 검토. 점검은 읽기 전용으로 진행했으며 코드는 변경하지 않았다.

## 총평

- 56개 페이지 전부 정상 렌더. HTTP 오류 0건, 콘솔 오류 0건, 런타임 예외 0건.
- typecheck / 테스트 27건 / 프로덕션 빌드 통과 유지.
- 치명(운영 중단·금전 사고)급 결함은 없음. 다만 아래 "중요" 항목들은 실사용 전 수정 권장.

## 1. 버그 / 오류 (심각도순)

### 중요

**B1. 회원 탈퇴 액션에 역할 검증이 없음** — `src/app/actions/donor.ts` `withdrawAccount`
후원자용 액션이지만 role 확인이 없어 사회복지기관·관리자 세션도 호출 가능. 사회복지기관가 실행하면 계정만 WITHDRAWN 이 되고 사회복지기관 프로필·MO 번호·정산계좌는 남아, 죽은 계정으로 후원이 계속 결제되는 고아 상태가 된다. 관리자가 실행하면 "본인 상태 변경 금지 / 마지막 SUPER_ADMIN 강등 금지" 가드를 우회해 자기 계정을 무력화할 수 있다.
→ 수정: 액션 초입에 `role !== 'DONOR'` 거부 + 사회복지기관/관리자에겐 별도 탈퇴 절차 안내.

**B2. 인증번호 만료 시 화면이 코드 입력 단계에 갇힘** — `donation-lookup-sheet.tsx`, `phone-link-form.tsx`
인증 5회 실패나 유효시간 만료 시 서버는 "처음부터 다시" 상태를 돌려주지만, 화면 단계 계산이 발송 상태(sendState)를 우선해 코드 입력 폼에 고정된다. 만료된 티켓으로 계속 제출되어 "유효시간이 지났습니다"만 반복되고, 번호 입력으로 돌아갈 방법이 없다(시트를 닫았다 다시 열어야 함). 휴대폰 연결 폼은 재발송 버튼조차 없음.
→ 수정: 서버가 step:'phone' 을 돌려주면 발송 상태를 리셋하고 번호 입력 화면으로 복귀 + "인증번호 다시 받기" 버튼 추가.

**B3. 정산 요청·지급에 동시성 방어 없음** — `src/server/services/settlement.ts`
정산 가능 금액 확인과 요청 생성 사이에 잠금·트랜잭션이 없어, 동시에 두 번 요청하면 둘 다 통과해 가용 잔액을 초과한 이중 요청이 생길 수 있다. 지급 완료 처리도 상태 확인과 원장 기록이 한 트랜잭션이 아니어서 관리자 이중 클릭 시 append-only 원장에 지급 분개가 중복될 수 있다. `withAdvisoryLock` 헬퍼가 준비돼 있는데 어디서도 호출되지 않음.
→ 수정: 요청 생성·지급 처리에 사회복지기관 단위 advisory lock + 트랜잭션 적용.

**B4. 관리자 콘솔 6개 페이지 가로 스크롤 발생 (1440px 기준)**
`/admin/fees`(+128px), `/admin/mo-messages` `/admin/payments` `/admin/refunds` `/admin/overlay`(각 +48px), `/admin/terms`(+28px). 원인은 `min-w-[720~900px]` 표가 가로 스크롤 컨테이너 밖으로 새는 것. 페이지 전체가 옆으로 밀린다.
→ 수정: 표 래퍼의 overflow 컨테이너 적용 확인(부모 flex 에 `min-w-0` 누락 지점 점검).

**B5. 구 브랜드명 '기브싸인'가 DB 데이터에 잔존**
코드에는 0건이지만 DB에 남아 화면에 노출: 관리자 계정 이름 "기브싸인 관리자"(콘솔 좌측 하단 프로필에 표시), 콘텐츠 2건(공지 "기브싸인 베타 서비스 안내" 등 → `/notice` 공개 노출), 약관 1건(→ `/terms` 공개 노출). 시드가 "이미 있으면 건너뛰기" 방식이라 기존 DB가 갱신되지 않았다. PC의 미리보기 DB에는 더 많이 남아 있을 것.
→ 수정: 시드 버전 3으로 올려 기존 행의 브랜드 문구를 UPDATE 하는 보충 시드 추가(자동 반영됨).

### 사소

**B6. 모바일 브라우저 테마색이 구 보라색** — `src/app/layout.tsx` `themeColor: '#6c4cf1'`. 모바일 주소창 색이 꿀벌 팔레트와 충돌. OG `siteName` 도 "기브싸인 BASIC" 로 구 워드마크 잔존.

**B7. 노랑 면 위 흰 글자 잔존 (자체 대비 규칙 위반, 대비 약 2.1:1)** — 후원 페이지 핵심 버튼 "문자 보내기"(`c/[code]/page.tsx`), `how-it-works` 안내 카드, 메인·이용방법의 스텝 번호 배지, PC 우측 메뉴 프로필 아바타. 특히 "문자 보내기"는 트래픽이 가장 많은 전환 버튼.

**B8. 콘솔 모바일 드로어 하단 64px 공백** — `console-shell.tsx` `inset-y-16` 이 top/bottom 을 모두 64px 로 잡아 드로어가 바닥에 닿지 않음(`top-16 bottom-0` 의도).

**B9. iOS 하단 탭이 홈 인디케이터에 가려질 수 있음** — 하단 내비에 `safe-area-inset-bottom` 미적용.

**B10. PC 우측 메뉴 중앙 정렬이 낮은 해상도에서 상단 잘림 가능** — sticky+translate 조합 특성상 뷰포트 높이가 약 690px 미만(작은 노트북)이면 로고·홈이 화면 위로 밀릴 수 있음. `top-1/2` 대신 뷰포트 높이 기반 clamp 권장.

**B11. 상태 라벨 문자열에 의존한 분기** — `my/page.tsx` 환불 배지 중복 방지를 `status.text.includes('환불')` 로 처리. 라벨 문구를 바꾸면 조용히 깨짐. enum(REFUND_REQUESTED/REFUNDED) 비교로 교체 권장.

**B12. 확인 만료 처리에 상태 로그 누락** — `donation-confirm.ts` 의 만료 전이만 DonationStatusLog 를 남기지 않아 감사 이력에 구멍.

**B13. 접근성 소소 결함** — 숨긴 aside(sr-only)에 포커스 가능한 링크가 남아 키보드 탭이 보이지 않는 요소에 걸림, 히어로 슬라이더가 `prefers-reduced-motion` 무시·키보드 포커스 시 자동전환 유지, 햄버거 버튼 `aria-expanded` 없음, Badge 노랑/초록 톤 일부 WCAG 대비 미달.

### 확인했고 문제 없는 것

- 브랜드 치환 부작용 없음: `givesign_session` 쿠키, `x-givesign-signature` 헤더, 시드 키워드 `MSG3QP7`, 코드 프리픽스 `GIV-`, 오버레이 테마 키 등 로직 식별자는 전부 온전.
- 후원확인(전화번호 조회)의 정보 보호: 마스킹 번호만 반환, 거래번호·결제수단 비노출, 번호당 발송 3회/10분 제한, 티켓 추측 불가 — 우회 경로 없음.
- 탈퇴 계정 차단: WITHDRAWN 상태는 세션 검증에서 걸러지고 세션도 전부 삭제됨.
- 멱등성 4중 방어, 정산 원장 append-only 트리거, 개인정보 3분리 저장 등 핵심 안전장치 유지.

## 2. UI/UX 개선 제안

### 우선순위 상

**U1. 설정 하위 페이지(한도·차단·동의)에 "← 내 정보" 백링크와 페이지 제목 추가.** 지금은 탭 하이라이트만 유지되고 내가 어디에 들어와 있는지, 어떻게 돌아가는지 표시가 없다.

**U2. 빈 상태를 행동 유도형으로.** EmptyState 컴포넌트에 버튼 슬롯을 추가해서 — 후원자 "후원 내역이 없습니다" → 후원확인/이용방법 버튼, 사회복지기관 "아직 후원 내역이 없습니다" → 후원 번호 안내 복사 버튼, 관리자 빈 목록 → MO 시뮬레이터 바로가기 버튼.

**U3. "문자 보내기" 버튼을 공통 primary(노랑 바탕+검은 글자)로 교체** — B7과 동일 건이지만 UX 관점에서도 최우선.

### 우선순위 중

**U4. 사회복지기관 대시보드의 "설정 필요" 항목 승격.** 연동 상태에 미완료가 있으면 목록 중간이 아니라 대시보드 최상단에 "다음 할 일" 배너로 노출 → 신규 사회복지기관의 온보딩 완주율에 직결.

**U5. 관리자 대시보드 섹션 순서 동적화.** 대기 건(정산 요청·신고·이상거래)이 1건이라도 있으면 "확인이 필요한 건"을 지표 위로 올리기 — 운영자의 첫 행동과 화면 순서가 일치.

**U6. Badge 톤 정리.** '필수' 약관·'고정' 콘텐츠에 경고(warning) 톤을 쓰고 있어 문제 신호로 오독됨 → brand/neutral 로. 감사 로그의 전 행 brand 배지는 강조 의미가 없어 회색 권장.

**U7. 관리자 리스크 지표 딥링크.** '오늘 한도 차단'과 '미해결 이상거래'가 같은 `/admin/risk` 로 가는데 필터 쿼리가 없어 착지 후 다시 찾아야 함 → `?filter=` 부여.

### 우선순위 하

**U8.** 콘솔 배경(#f7f5ef)과 공개 영역 배경(#faf6ea) 하드코딩 불일치 → 토큰화. **U9.** 후원 내역 요약 라벨 "N건 후원"이 결제 완료 건수인데 전체 기록 수와 혼동 여지 → "결제 완료 N건" 으로. **U10.** 사용하지 않는 PC aside(sr-only) 제거로 코드 정리. **U11.** 히어로 슬라이더 reduced-motion 대응.
