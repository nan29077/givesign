# 기브싸인 제품 전환 계획서

작성일: 2026-08-31
결정: 사회복지기관 문자후원 플랫폼 → **문자 한 통으로 끝나는 결제·포인트 충전 서비스**로 완전 전환
전제: 브랜드 분리(토네이도/도네이도 제거)와 게임 오버레이 삭제는 완료된 상태

---

## 0. 요약

바뀌는 것은 "누가 누구에게 왜 돈을 보내는가" 하나입니다.

| | 도네이도(기존) | 기브싸인(전환 후) |
|---|---|---|
| 돈을 받는 쪽 | 사회복지기관 개인 | 사회복지기관(게임·멤버십·콘텐츠) |
| 결제 사유 | 응원 후원 | 포인트·캐시 선불 충전 |
| 결제 후 일어나는 일 | 방송 화면 오버레이 + 유튜브 댓글 | **사회복지기관에 충전 반영(적립 연동)** |
| 최종 사용자 | 시청자 | 사회복지기관 후원자 |

그대로 쓰는 자산이 더 많습니다. MO(수신문자) → 확인 링크 → 내통장결제 → MT(결과문자) 로 이어지는 결제 파이프라인, 멱등성 4중 방어, 한도·이상거래, 정산 원장, 개인정보 3분리 저장, 관리자 콘솔은 **결제 인프라라서 그대로 살아남습니다.** 걷어내는 것은 방송 계층이고, 새로 만드는 것은 사회복지기관 연동 계층입니다.

## 1. 구성요소 판정

### 1-1. 그대로 유지 (결제 인프라)

- MO 수신 · MT 발송 어댑터, MO 시뮬레이터, 웹훅
- 헥토 내통장결제 어댑터, PIN 인증, 결제 시도·거래·환불
- 멱등키, 한도 정책·카운터, 이상거래 탐지
- 정산 원장(append-only), 수수료 정책, 원천징수
- 관리자 콘솔 대부분, 약관·동의·감사로그·문의

### 1-2. 걷어냄 (방송 계층) — 1단계 대상

| 대상 | 위치 |
|---|---|
| 오버레이 | `src/app/overlay/**`, `src/app/api/overlay/**`, `src/components/overlay/**`, `studio/overlay`, `overlay-bus`, `overlay-connections`, `overlay-tiers`, `overlay-effect-catalog` |
| TTS | `src/app/api/tts/**`, `src/server/services/tts/**`, `TtsSetting` |
| 유튜브 | `src/app/studio/youtube`, `src/app/api/youtube/**`, `mock/youtube`, `adapters/youtube`, `YouTubeConnection` · `YouTubeBroadcast` · `YouTubeChatDelivery` |
| 방송 송출 | `broadcast-dispatch`, `Donation.broadcast*` 계열 상태 |
| 모델 | `OverlaySetting` · `OverlayTier` · `OverlayEvent` · `TtsSetting` · `YouTube*` |

관리자 메뉴(유튜브·TTS·오버레이)는 이미 제거되어 있습니다.

### 1-3. 뜻을 바꿈 (개명 + 재정의) — 3단계 대상

| 지금 | 전환 후 | 메모 |
|---|---|---|
| `CreatorProfile` | `MerchantProfile`(사회복지기관) | 심사·상태 흐름은 그대로 |
| `CreatorCode` (GIV-XXXX) | 사회복지기관 코드 | 충전 페이지 주소 `/c/[code]` 유지 가능 |
| `DonorProfile` | `PayerProfile`(결제 회원) | 계정 연결·온보딩 그대로 |
| `Donation` | `Charge`(충전 거래) | 금액·상태·원장 연결 그대로 |
| `DonationLimitPolicy` · `DonationCounter` | `ChargeLimitPolicy` · `ChargeCounter` | 한도 로직 동일 |
| 후원샵 `/c/[code]` | 충전 페이지 | 문구·구성 전면 교체 |
| 스튜디오 | 사회복지기관 콘솔 | 충전 내역 · 상품 · 정산 |
| `BannedWord` · `Report` · 닉네임 | 대부분 불필요 | 후원 메시지 노출이 없어짐 |

### 1-4. 새로 만듦 (핵심 신규) — 4단계 대상

1. **충전 반영 연동** — 결제 성공 시 사회복지기관에 포인트를 적립시키는 서버 대 서버 연동. 기존 "유튜브 댓글 전송"이 차지하던 자리다. 어댑터 인터페이스 + mock 으로 시작하고, 전송 실패가 결제 결과를 바꾸지 않는다는 기존 원칙(절대 규칙 3)을 그대로 승계한다.
2. **후원 항목** — 금액 구간 대신 "5,000원 = 500캐시" 같은 상품 정의.
3. **사회복지기관 온보딩** — 사회복지기관 가입 신청 자리를 서비스 도입 신청으로 교체(공개 화면은 이미 `/support` 로 연결됨).
4. **가맹 정산** — 원장 구조는 유지, 정산 주체만 개인 → 사업자.

## 3. 먼저 확인이 필요한 규제 사항

법률 자문이 아니라 검토가 필요한 지점의 목록입니다. 변호사·전문가 확인이 필요합니다.

- **선불전자지급수단**: 후원자가 미리 충전한 금액을 사회복지기관에서 쓰는 구조는 전자금융거래법상 선불전자지급수단 발행·관리업에 해당할 수 있습니다. 기브싸인가 직접 잔액을 보유하는지, 아니면 결제 대행만 하고 포인트는 사회복지기관가 발행하는지에 따라 결론이 갈립니다. **이 구조 선택이 4단계 설계를 지배하므로 가장 먼저 정해야 합니다.**
- 통신과금(휴대폰 결제)과의 구분 — 현재는 문자를 트리거로 쓰고 결제는 내통장결제라 통신과금이 아니지만, 문구가 오해를 주지 않아야 합니다.
- 미성년자 충전 한도 및 청약철회·환불 정책(콘텐츠 이용권 특성상 기존 후원 환불 정책과 다릅니다).
- 기존 약관 2종(`/terms`, `/terms/e-finance`)은 후원 전제로 쓰여 있어 전면 재작성 대상입니다.
