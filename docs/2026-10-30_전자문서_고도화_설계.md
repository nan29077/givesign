# 기브싸인 전자문서 고도화 설계 (2026-10-30)

Codex 1차 구현(작성 요청 링크 · 충전/정액 신청 · 관리자 승인)을 이어받아 PaySign 같은 전자문서 서비스 수준으로 올리는 계획이다.
Codex 작업이 커밋되면 그 위에서 진행한다. 아래 순서대로 만들고 각 단계마다 테스트와 커밋을 한다.

참고: paysign.co.kr 은 이 작업 환경에서 접속이 막혀 있어 직접 보지 못했다. 국내 전자계약 서비스의 일반적인 구성(템플릿, 다중 서명자, 문자·알림톡 발송, 서명 순서, 완료 증명서, 감사추적, 충전·정액 요금)을 기준으로 설계했다. 화면 캡처나 기능 목록을 받으면 그에 맞춰 조정한다.

## 1. 이어받을 때 바로잡을 것 (Codex 1차 구현)

| 현재 | 문제 | 바꿀 것 |
|---|---|---|
| 잔액·정액·시범 제공량을 `system_setting` 키 하나에 JSON 으로 저장 | 거래 원장이 없어 잔액의 근거를 댈 수 없고, 정정·환불을 추적할 수 없다 | `edoc_wallet`(현재 잔액) + `edoc_ledger`(append-only 원장, 정산 원장과 같은 규칙) |
| 신청·사용·스냅샷을 `system_setting` 행으로 하나씩 생성 | 조회·집계·인덱스가 불가능하고 설정 테이블이 무한히 커진다 | 전용 테이블: `edoc_billing_request`, `edoc_envelope` 등 |
| 문서 1건 = 수신인 1명 | 약정서·동의서는 후원자 + 법정대리인 + 기관 담당자처럼 여러 명이 서명한다 | 봉투(envelope) + 서명자(signer) 구조, 서명 순서 |
| 링크를 화면에 한 번 보여 주고 끝 | 기관이 직접 복사해 보내야 한다 | MT 문자 발송·재발송·자동 리마인드(기존 문자 어댑터 사용, mock 명시) |
| 완료 증거는 제출 시각·접속 기록 | 분쟁 때 제출할 증명서가 없다 | 완료 증명서 PDF + 원본 해시 + 감사추적 해시 체인 |

## 2. 데이터 구조 (새 마이그레이션)

- `EDocWallet` — 기관당 1행. 충전 잔액(원), 시범 잔여 건수, 현재 정액 구독 참조. 행 잠금으로 차감한다.
- `EDocLedger` — append-only(DB 트리거로 UPDATE/DELETE 차단). 종류: `TOPUP`(충전 승인), `PLAN_GRANT`(정액 제공), `USE`(발송 차감), `REFUND`(발송 취소 환원), `EXPIRE`(정액 만료 소멸), `ADJUST`(관리자 정정, 사유 필수). 금액·건수, 잔액 스냅샷, 공급가액·부가세 분리(절대 규칙 8), 멱등키 유니크.
- `EDocPlan` — 관리자가 정하는 요금제. 충전형(건당 단가, 충전 보너스 구간) / 정액형(월 요금·제공 건수·초과 단가) / 시범 제공량. `effectiveFrom/To` 로 적용 판단(규칙 8과 같은 방식).
- `EDocSubscription` — 기관의 정액 구독. 기간, 제공 건수, 사용 건수, 상태(ACTIVE/EXPIRED/CANCELLED). 자동 갱신은 하지 않는다(결제 연동 전).
- `EDocBillingRequest` — 충전·정액 신청. 관리자 승인은 실제 입금·계약 확인 체크가 필요하다(Codex 원칙 유지). 승인하면 원장에 기록한다. 세금계산서 발행 여부도 기록한다.
- `EDocEnvelope` — 발송 단위. 서식 스냅샷(암호화) + SHA-256, 상태(DRAFT/SENT/IN_PROGRESS/COMPLETED/DECLINED/EXPIRED/CANCELLED), 만료일, 서명 순서(동시/순차), 연결 정보(후원자·캠페인·정기후원 약정).
- `EDocSigner` — 서명자. 역할(후원자·법정대리인·자원봉사자·기관 담당자), 이름·전화는 암호화+해시+마스킹, 1회용 토큰 해시, 순서, 인증 방식(문자 OTP / 없음), 상태, 서명 이미지·입력값 암호화, IP·UA·시각.
- `EDocEvent` — 감사추적. 생성·발송·열람·OTP 인증·서명·거절·완료·취소·다운로드. 각 행에 직전 행 해시를 이어 붙인 해시 체인으로 위변조를 검출한다.

기존 `DocumentTemplate`·`DocumentSubmission` 은 상품(문서 상품) 흐름이 쓰므로 그대로 둔다. 전자문서 센터는 봉투 구조를 쓰고, 서식만 공유한다.

## 3. 과금 규칙

- 차감 시점: **발송할 때 1건**. 재발송·열람·서명·리마인드에는 차감하지 않는다(Codex 원칙 유지).
- 차감 순서: 정액 잔여 → 시범 잔여 → 충전 잔액. 모두 부족하면 발송하지 않는다.
- 서명자가 여럿이면 봉투 1건으로 센다. 대량 발송은 수신인 수만큼 센다.
- 아무도 열람하지 않은 상태에서 기관이 발송을 취소하면 1건을 환원한다(`REFUND`). 열람 이후에는 환원하지 않는다.
- 정액 기간이 끝나면 남은 제공량은 `EXPIRE` 로 소멸 기록한다(배치).
- 잔액이 기준 이하로 떨어지면 기관 담당자에게 알림을 보낸다(인앱 + 문자).
- 결제 연동 전이므로 충전·정액은 "신청 → 관리자가 입금 확인 후 승인" 방식이다. 가상계좌·카드 결제 연동은 어댑터 인터페이스와 mock 으로만 만들고 화면에 mock 임을 표시한다(절대 규칙 2).

## 4. 사회복지기관용 기본 서식 (프리셋)

후원약정서(일시·정기, CMS 출금 동의 포함), 자원봉사 신청서, 자원봉사 활동 확인서, 개인정보 수집·이용 동의서, 초상권(사진·영상) 이용 동의서, 프로그램 참가 신청서, 법정대리인 동의서(미성년), 후원 물품 기증서, 서비스 이용 계약서, 후원금 사용 동의서.

- 서식마다 입력 항목(이름·연락처·주소·금액·주기·서명·체크박스·날짜)과 필수 여부, 서명자 역할을 미리 정해 둔다.
- 기관이 복제한 뒤 문구를 고쳐 쓸 수 있다. 법률 검토를 거친 표준 문안이 아니라는 안내를 표시한다.
- **기부금영수증은 전자문서 서식으로 만들지 않는다.** 영수증 대장(`/studio/receipts`)에서만 발급하고, 전자문서 센터에서는 바로가기만 둔다. 세법상 발급 통제를 우회하지 않기 위해서다.
- 후원약정서가 완료되면 정기후원 약정과 연결할 수 있게 한다. 실제 출금 동의는 기존 정기후원 동의 절차를 그대로 거친다.

## 5. 기관 콘솔

- **전자문서 센터** 대시보드: 이번 달 발송·완료·대기·만료 건수, 잔액·정액 잔여, 완료율.
- **발송**: 서식 선택 → 서명자 추가(역할·순서) → 미리 채울 값 → 문자 발송 미리보기 → 발송. 발송 전에 차감될 건수와 출처(정액/시범/충전)를 보여 준다.
- **대량 발송**: CSV(이름·휴대폰·미리 채울 값) 업로드 → 검증 결과 미리보기 → 일괄 발송. 잔액이 부족하면 시작하지 않는다.
- **문서함**: 상태별 필터, 서명자별 진행 상황, 재발송·리마인드·취소, 완료본 PDF·증명서 내려받기(열람할 때마다 감사로그).
- **서식 관리**: 프리셋 복제, 항목 편집기, 서명자 역할 지정, 미리보기.
- **충전·정액**: 현재 요금제, 잔액·정액 잔여, 신청, 원장(사용·충전·환원·소멸 내역), 월별 사용 통계.

## 6. 서명자 화면 (`/sign/[token]`)

- 모바일 우선. 문서 내용 → 입력 → 서명(자필 패드) → 확인 → 제출.
- 본인 확인: 기본은 문자 OTP(받은 번호로 인증번호). 공동인증서·카카오 인증서·PASS 는 어댑터만 두고 mock 으로 표시한다.
- 거절할 수 있다(사유 입력). 순차 서명이면 다음 서명자에게 자동으로 문자를 보낸다.
- 완료하면 서명자에게 완료본 열람 링크를 문자로 보낸다.

## 7. 관리자

- 요금제 관리(충전 단가·보너스 구간, 정액 요금·제공량·초과 단가, 시범 제공량, 적용 기간).
- 충전·정액 신청 승인·반려(입금 확인 체크, 세금계산서 발행 여부), 관리자 정정(사유 필수, `ADJUST` 원장).
- 기관별 잔액·사용량·완료율, 전체 매출(공급가액·부가세 분리), 월별 추이.
- 정액 만료 배치, 잔액 부족 기관 목록.
- 서명 분쟁 대응: 봉투 감사추적과 해시 체인 검증 결과 보기.

## 8. 보안·법적 고려

- 서명자 개인정보는 해시 + 암호화 + 마스킹으로 나눠 저장한다(절대 규칙 6).
- 완료본은 발송 당시 서식 스냅샷과 입력값으로 만든다. 발송 뒤 서식을 고쳐도 바뀌지 않는다.
- 완료 증명서에는 문서 해시, 서명자별 인증 방식·시각·IP, 감사추적 해시 체인 끝값을 담는다.
- 공인전자문서 중계·TSA(시점확인)는 계약 전이라 연결하지 않는다. 화면에 "기브싸인 내부 기록"임을 밝힌다.
- 보관 기간은 기관 설정으로 정하고(기본 5년), 기간이 지나면 파기 예정 목록에 올린다. 자동 삭제는 하지 않는다.

## 9. 진행 순서

1. Codex 커밋을 가져와 테스트·빌드 확인
2. 스키마·마이그레이션(지갑·원장·요금제·구독·신청·봉투·서명자·이벤트) + 기존 `system_setting` 데이터 이관
3. 과금 서비스(차감·환원·만료·정정) + 테스트
4. 봉투·서명자·감사추적 서비스 + 서명자 화면 + 문자 발송 + 테스트
5. 기관 콘솔(센터·발송·대량 발송·문서함·충전/정액) 
6. 관리자(요금제·신청 승인·기관별 현황·만료 배치)
7. 프리셋 서식 10종, 완료 증명서 PDF
8. 전체 검증(타입·린트·테스트·빈 DB·빌드·e2e·화면 확인) → 커밋·푸시 → PC 반영
