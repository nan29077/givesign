## 1. 왜 복구했는가

`99da66b` 는 24개 파일 3,491줄을 삭제했다. 이 중 **E2E 스크립트 9개(약 220건 검증)** 는
기브싸인에서 **화면이 깨졌는지 확인하는 유일한 수단**이었다.

- `tests/*.test.ts` (Vitest 162건) — 서버 로직만 본다. 화면은 보지 않는다.
- `e2e/*.mjs` — 실제 크로미움을 띄워 로그인하고 클릭·입력한다.

삭제 이후 화면 검증은 0건이었다. 특히 그 직후 Codex 가 PC 웹 후원을 PIN 인증 흐름으로
전면 교체(`78925cd`, `6a042a9`)했기 때문에, **가장 크게 바뀐 결제 화면이 검증 없이 배포되는 상태**였다.

## 2. 어떻게 복구했는가

옛 파일을 그대로 되돌리지 않았다. 되돌렸다면 상당수가 FAIL 이었다.
예: `gap-e2e.mjs` 가 검사하던 문구 `"본인 인증 후 바로 결제"` 는 현행 코드에 **0개**다(PIN 전환으로 사라짐).

그래서 **현행 화면 기준으로 다시 썼다.**

| 조치 | 내용 |
|---|---|
| 위치 이동 | 저장소 루트 → `e2e/` 디렉터리 (루트 산재 → "안 쓰는 파일" 오해의 원인이었음) |
| 실행 경로 부여 | `npm run test:e2e` 추가 + `e2e/run-all.mjs` 실행기 |
| 재현성 확보 | 스크립트마다 DB 초기화·재시드 → 실행 순서에 결과가 좌우되지 않음 |
| 이식성 확보 | 크로미움 경로를 하드코딩하지 않음 (`E2E_CHROMIUM`, `E2E_BASE` 환경변수) |
| 기능 변화 대응 | 관리자 화면 목록을 **사이드바 링크에서 자동으로 뽑는다**. 메뉴가 늘거나 줄어도 스크립트를 고칠 필요가 없다. 자체방송(RTMPS)처럼 통째로 정리된 기능은 "있으면 검증, 없으면 잔재 없음 확인"으로 처리한다 |
| 문서화 | `e2e/README.md` — 실행법·구성·삭제 금지 사유 |

### 이번 복구로 브라우저에서 실제 확인된 것

1. **PC 웹 후원 PIN 전 구간** — 금액·메시지 선택 → 번호 입력 → PIN 링크 문자 발송 →
   문자의 링크에서 PIN 6자리 입력 → 결제 완료 → 후원샵 화면이 폴링으로 완료 감지 →
   최근 후원 목록 노출. **PIN 링크 1회용 차단**까지 확인.
2. **정산 요청 → 최고관리자 알림 도착** — 사회복지기관가 정산을 요청하면 최고관리자
   알림 버튼에 미읽음 배지가 붙고, 알림함에 `새 정산 요청이 접수되었습니다` 가 들어오며
   `/admin/settlements` 목록에도 올라온다. 클릭만으로 전 구간 확인.
3. **원천징수 계산** — 정산 가능금 7,488원 구간에서 소득세 340원 < 1,000원 →
   `0원 (소액부징수)` 로 표시. 옛 3.3% 일괄 계산 흔적 없음.
4. **오버레이 파이프라인** — `/overlay/{id}?preview=1&debug=1` 에서 SSE `연결됨` 확인 후

   토큰 없는 접근은 `접근 권한이 없습니다 (401)`.
5. **민감자료 권한** — 지급대행/원천징수 CSV 는 비로그인 401, 대상 미선택 400,

## 5. 추가 수정 (지시받아 반영 완료)

- **정산 요청 내역의 원천징수 열이 `-0원` 으로 표시되던 문제 수정.**
  공제액을 음수로 보이려는 의도였으나(`-{formatWon(r.withholding)}`), 소액부징수로 0원일 때
  `-0원` 이 되어 어색했다. 원천징수가 있을 때만 `-` 를 붙이고 색도 빨간색으로 두며,
  0원이면 `0원` 을 흐린 색으로 표시하도록 바꿨다. (`src/app/studio/settlement/page.tsx`)
- 이 회귀를 막기 위해 `round10-e2e.mjs` 에 검사 1건을 추가했다:
  정산 요청 직후 화면에 `-0원` 문자열이 없어야 한다. → **전체 417건 전건 통과.**
