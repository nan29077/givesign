## A-2. 금칙어를 설정하면 실제로 어떻게 작동하나

**설정 위치**: 사회복지기관 관리자 → `금칙어 · 차단`

단어를 등록할 때 처리 방식을 셋 중 하나로 고릅니다.

| 방식 | 동작 | 후원금 |
|---|---|---|
| **차단 (BLOCK)** | 후원 자체가 접수되지 않음. 상태 `CONTENT_BLOCKED` | **결제 안 됨** |
| **마스킹 (MASK)** | 해당 단어만 `****` 로 가려서 노출. 나머지 문장은 그대로 | 정상 결제 |
| **표시 (FLAG)** | 화면에는 그대로 노출, 내부 기록만 남김 | 정상 결제 |

**문자 한 건이 들어왔을 때 거치는 순서** (`filterContent`)

1. 제어문자·보이지 않는 문자·연속 공백 정리
2. **개인정보 자동 마스킹** — 주민등록번호, 카드번호, 휴대폰·유선번호, 계좌번호, 이메일을 자동으로 가리고 URL은 `[링크 차단]` 으로 치환합니다. **이건 금칙어와 무관하게 항상 적용**되며 사회복지기관가 끌 수 없습니다.
3. **금칙어 적용** — 전역 금칙어(플랫폼 공통)와 내 금칙어를 함께 불러와 적용합니다. 대소문자를 가리지 않고 문장 중간에 있어도 잡습니다.
4. **길이 제한** — 오버레이 설정의 최대 글자수(기본 80자)로 자릅니다.

**BLOCK 이 걸리면 일어나는 일**

- 후원 상태가 `CONTENT_BLOCKED` 이 되고 **결제 요청 자체가 나가지 않습니다** (출금 없음)
- 유튜브 댓글·오버레이에도 전달되지 않습니다
- 후원자에게는 안내 문자(MT)가 발송됩니다
- 원문은 분쟁 대응을 위해 **암호화해서 보관**하고, 화면에는 절대 노출하지 않습니다

**적용 범위**

- 내 금칙어는 **내 채널에만** 적용됩니다. 다른 사회복지기관에게는 영향이 없습니다.
- 전역 금칙어는 통합 관리자만 등록·수정할 수 있고, 사회복지기관 화면에는 조회만 됩니다.
- 사용 중지로 바꾸면 삭제하지 않아도 즉시 적용이 멈춥니다.

**후원자 차단**은 별개 기능으로, 차단된 후원자의 문자는 내용과 무관하게 접수되지 않습니다(`LIMIT_BLOCKED`).

## A-3. 개선하면 좋을 점 (지시하시면 진행)

1. **테스트 입력창이 없습니다.** 등록한 금칙어가 실제로 어떻게 걸리는지 문장을 넣어 미리 확인할 수 없어, 사회복지기관가 실제 후원이 올 때까지 확인이 불가합니다.
2. **차단 이력이 사회복지기관에게 안 보입니다.** 어떤 단어로 몇 건이 차단됐는지 볼 수 없어 금칙어를 조정할 근거가 없습니다.
3. **우회 표기를 못 잡습니다.** `ㅅㅂ`, `시1발`, `시 발` 같은 변형은 별도 등록해야만 걸립니다.
4. 자주 쓰는 비속어 **기본 세트가 없어** 사회복지기관가 처음부터 직접 입력해야 합니다.

## B-1. 원인

직전 작업에서 발견해 고친 문제와 **같은 원인**이었습니다.

후원페이지 설정 화면은 라이브 주소 입력칸이 `youtubeLiveUrl` / `instagramLiveUrl` / `tiktokLiveUrl` 세 개로 바뀌어 있었는데, **저장 로직은 예전 이름(`liveUrl`) 하나만 읽고 있었습니다.** 그래서

- 저장 시 라이브 주소가 항상 빈 값으로 인식됨
- → "방송중 스위치를 켜려면 링크를 먼저 입력해 주세요" 로 **저장이 거부됨**
- → 아무것도 저장되지 않으니 **새로고침하면 스위치가 꺼진 상태**로 돌아가고
- → 후원페이지에도 온에어·두근두근 효과가 나타나지 않음

두 증상이 하나의 원인이었습니다.

# C. 정산 프로세스 점검 결과

## C-1. 지금 구현되어 있는 것 (정상)

```
사회복지기관                          통합 관리자
────────────────────────────────────────────────────────
정산계좌 등록
   ↓
[관리자] 실명확인 완료 처리 ────────→ verified = true
   ↓
정산 요청 (금액 + 메모)
   ├ 정산 가능 금액 초과 → 거부
   ├ 계좌 미인증 → 거부
   ├ 동시 요청 직렬화(advisory lock)
   └ 원천징수 3.3% 자동 계산
   ↓
                                    REQUESTED 목록에 표시
                                       ↓ 검토중 / 승인 / 반려
                                    APPROVED
                                       ↓ 지급 완료 처리
                                    PAID
                                       ├ 승인 상태 재확인
                                       ├ 계좌 인증 재확인
                                       ├ 잔액 재확인
                                       └ 원장에 PAYOUT · 원천징수 분개 기록
```

안전장치는 잘 들어가 있습니다. 요청 금액 초과 차단, 계좌 미인증 차단, 동시 클릭 시 이중 지급 방지, 승인 없이 지급 불가, 원장 append-only(수정·삭제 불가) 모두 실행으로 검증된 상태입니다.

## C-2. 지급대행으로 운영하려면 빠진 것

말씀하신 **지급대행 방식**은 "플랫폼이 정산 내역을 정해진 엑셀 양식으로 취합해 업로드하면 대행사가 각 계좌로 일괄 이체" 하는 구조입니다. 현재 시스템에는 그 흐름에 필요한 것들이 없습니다.

| # | 빠진 것 | 왜 문제인가 |
|---|---|---|
| 1 | **주민등록번호 수집 경로 없음** | 원천징수 3.3% 를 계산만 하고 있고, **국세청 지급명세서를 낼 수 없습니다.** 원천징수는 했는데 신고를 못 하는 상태입니다. |
| 2 | **지급대행 업로드 파일 생성 없음** | 승인 건을 엑셀/CSV 로 내려받는 기능이 없어, 관리자가 손으로 옮겨 적어야 합니다. 금액·계좌 오타 시 곧바로 오지급입니다. |
| 3 | **일괄 처리 없음** | 승인·지급이 한 건씩만 됩니다. 사회복지기관가 늘면 관리자가 감당하지 못합니다. |
| 4 | **지급 실패 상태가 없음** | 대행사에서 계좌 오류로 반송되어도 기록할 자리가 없습니다. 이미 `PAID` 로 원장에 기록된 뒤라 되돌리려면 수동 조정이 필요합니다. |
| 5 | **반려 사유가 사회복지기관에게 안 보임** | 관리자가 메모를 남겨도 사회복지기관 화면에 표시되지 않습니다. 왜 반려됐는지 알 수 없습니다. |
| 6 | **상태 변경 알림 없음** | 승인·반려·지급 완료 시 사회복지기관에게 알림이 가지 않습니다. 직접 들어와서 확인해야 합니다. |
| 7 | **계좌 실명확인이 수동** | 관리자가 눈으로 보고 버튼을 누르는 구조입니다. 예금주 불일치를 걸러낼 방법이 없습니다. |
| 8 | **정산 화면 섹션이 한 페이지에 6개** | 스크롤이 길어 원하는 정보를 찾기 어렵습니다. (말씀하신 탭 개편 대상) |

## C-3. 주민등록번호 취급에 대한 의견

요청하신 대로 **출금 요청 시 입력 → 원천징수 신고에 사용 → 신고 후 즉시 폐기** 방식으로 만들겠습니다. 다만 주민등록번호는 개인정보보호법상 **가장 엄격하게 다뤄지는 고유식별정보**라 아래를 함께 적용할 것을 권합니다.

- **암호화 저장 필수** (법적 의무). 기존 계좌번호와 동일하게 AES 암호화 + 화면에는 `901010-1******` 형태 마스킹만 노출
- **원문 조회 경로를 두지 않음.** 지급명세서 생성 시에만 서버 내부에서 복호화
- **별도 수집 동의** 를 체크박스로 받고 동의 이력을 남김 (고유식별정보는 다른 개인정보와 분리 동의가 원칙)
- **자동 파기**: 신고 완료 표시 시 즉시 삭제 + 미신고분도 보관 기한(예: 지급일로부터 6개월) 경과 시 자동 삭제하는 배치
- **파기 이력 기록** — 언제 무엇을 지웠는지 남겨야 분쟁·감사 시 증명됩니다

> 참고: 세법상 원천징수영수증·지급명세서 관련 서류는 **5년 보존 의무**가 있습니다. "신고 후 즉시 폐기" 는 주민등록번호에 한정하고, 지급명세서 자체는 보존하는 형태가 안전합니다. 최종 보관 기간은 **세무 자문을 받아 확정**하시길 권합니다. 저는 화면 안내 문구를 요청하신 취지대로("원천징수 신고 목적으로만 사용하며 신고 완료 후 즉시 파기합니다") 넣되, 실제 파기 시점은 나중에 설정으로 조정할 수 있게 만들겠습니다.

# D. 개발 계획 (지시하시면 진행)

## 1단계 — 정산 관리 탭 개편

후원 설정 탭과 **똑같은 디자인**으로 상단 탭을 붙이고 섹션을 나눕니다.

| 탭 | 담을 내용 |
|---|---|
| **정산 현황** | 요약 타일 + 캘린더(일별 후원 합계) |
| **정산 요청** | 요청 폼 + 요청 내역 |
| **정산 계좌** | 계좌 등록·수정, 실명확인 상태 |
| **정산 원장** | 누적 요약 + 분개 내역 |

## 2단계 — 출금 요청 시 주민등록번호

- 정산 요청 폼에 주민등록번호 입력 + **별도 수집 동의 체크박스**
- 안내 문구: *"입력하신 주민등록번호는 소득세법에 따른 원천징수 신고 목적으로만 사용되며, 신고 완료 후 즉시 파기합니다. 암호화되어 저장되고 어떤 화면에도 원문이 표시되지 않습니다."*
- AES 암호화 저장 + `901010-1******` 마스킹 표시
- 이미 등록된 경우 재입력 없이 진행(마스킹 표시 + "변경" 버튼)
- 신고 완료 처리 시 자동 파기 + 파기 이력 기록

## 3단계 — 지급대행 정산 로직

- **정산 요청 목록 일괄 처리** — 체크박스 다중 선택 → 일괄 승인 / 일괄 반려
- **반려 사유 필수 입력** → 사회복지기관 화면에 표시 + 알림 발송
- **지급대행 파일 다운로드** — 승인 건을 `은행코드 / 계좌번호 / 예금주 / 실지급액 / 적요` 엑셀로 생성
- **지급 결과 업로드** — 대행사 결과 파일을 올려 성공/실패를 반영
- **지급 실패 상태(`PAYOUT_FAILED`) 신설** — 실패 건은 원장에 반대 분개로 환입 후 재요청 가능
- **상태 변경 알림** — 승인·반려·지급 완료·지급 실패 시 사회복지기관에게 알림
- **원천징수 신고 자료** — 기간별 지급명세서 산출용 내역 다운로드

## 4단계 — 이미지 첨부

프로필 캐릭터·후원페이지 배너에 **URL 입력 + 파일 업로드**를 함께 제공합니다.

- 드래그&드롭 또는 파일 선택
- 형식 제한(jpg/png/webp), 용량 제한(예: 5MB), 이미지 실제 여부 검증
- 업로드 전 미리보기 + 정사각 크롭(프로필)
- 저장 위치는 **결정이 필요합니다** — 아래 참조

# E. 진행 전 확인이 필요한 것
