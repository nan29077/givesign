## 0. 결론 한 줄

**뼈대는 잘 짜여 있지만, 지금의 기브싸인은 "AI 가 A~Z 를 스스로 처리하는 시스템"이 아니라 "담당자가 각 단계 버튼을 누르는 반자동 콘솔 + 외부 연동은 전부 mock" 상태다.**

| 비전의 요소 | 현재 | 판정 |
|---|---|---|
| AI 가 콘텐츠를 **스스로** 만든다 | 담당자가 "자동으로 만들기" 버튼을 눌러야 1건 생성. 캠페인 등록·기간·주기에 따른 자율 생성 없음. 생성 자체도 LLM 이 아니라 서식 치환(mock) | **없음** |
| 숏폼·쇼츠·카드뉴스·피드를 만든다 | SVG 장면 3~6장 + 자막(SRT) + 캡션. mp4·음성·AI 이미지·카드뉴스 세트 없음 | **부분** |
| 유튜브·인스타·페북·틱톡에 **자동 등록** | 예약 게시 큐·재시도·고착 복구는 구현. 실제 OAuth·업로드 어댑터 0개. 틱톡은 enum 에도 없음 | **없음(실연동)** |
| 콘텐츠를 보고 후원하면 후원자 관리 자동 | 유입 추적(src/cid 쿠키)→전환 집계, 전화번호 기준 한 사람 통합, 세그먼트 조회 — 구현. 다만 세그먼트는 "보여 주기만" 하고 후속 액션 자동화 없음 | **부분** |
| 후원금 입금 자동 확인 | 모든 경로가 `executePayment` 한 곳에서 자동 확정·정산 원장 기록·대사 큐 — 구현. 단 그 앞의 PIN 인증은 헥토 어댑터 포함 전부 mock, 카드·간편결제·가상계좌 없음 | **구현됨(mock 뒤)** |
| 기관 등록/기본 세트 전자문서로 약정서·영수증·감사편지 자동 발송 | 약정서는 코드 고정 스냅샷(기관 서식 미사용). 영수증은 MONTHLY 기관만 자동, 기본값 YEARLY 는 수동 버튼. **감사장(감사편지) 전자문서는 존재하지 않음**(문자 1통). 기관이 올린 PDF 서식은 수동 "서명 요청" 전용 | **부분 → 비전과 가장 멀다** |
| 자원봉사도 같은 방식 | 신청·승인·활동 기록·1365 CSV 구현. 모집 공고 개체·모집 콘텐츠·리마인드·활동 후 확인서/감사장 자동 발송 없음. 신청서 링크 안내는 `notify` 미전달로 안 나감 | **부분** |
| 관리자는 승인만 한다 | 승인 지점은 있지만 흩어져 있다(콘텐츠·봉사·영수증·전자서명·환불·알림톡이 한 대기함에 없음). 자동 승인은 콘텐츠 1종, 자동 승인돼도 게시 예약은 수동 | **부분** |
| 전체를 묶는 자동 실행 계층 | 워크플로/저니 엔진·이벤트 버스 없음. 후속 처리는 `charge-flow.ts` 안 하드코딩 + 크론 8개로 분산. `bullmq` 의존성은 있으나 미사용 | **없음** |

잘 된 점(유지할 것): 모든 외부 연동이 "mock 은 성공을 꾸미지 않는다 / 운영에서 `*_ENABLED=true`+mock 이면 부팅 거부" 로 fail-closed 되어 있고, 멱등(월간 안내·콘텐츠 단계·게시·정기출금)·조건부 선점·append-only 원장·인가(기관 소유 확인)가 일관되다. 따라서 **아래 갭은 "뼈대 위에 층을 올리는 일"이고 뒤집는 일이 아니다.**

## 2. 비전과 어긋나는 핵심 갭 7가지

1. **"AI" 가 없다.** `CONTENT_PROVIDER` live 어댑터 파일이 없고, LLM 은 대본 외 어디에도 안 쓰인다. 지금 "자동 생성" 은 템플릿 치환이다.
2. **스스로 움직이지 않는다.** 콘텐츠 생성·게시 예약·약정 재안내·영수증(YEARLY)·봉사 후속 — 비전상 자동이어야 할 것이 전부 담당자 버튼이다. 자율 트리거는 월간 안내·정기 출금·정산 3개뿐이다.
3. **전자문서 두 체계가 따로 있고, 자동 흐름은 둘 다 안 쓴다.** 약정서/신청서는 코드 고정 스냅샷(`agreement_document`), 기관 서식+PDF 편집+서명(`DocumentTemplate`+`EDocEnvelope`)은 수동 서명 요청 전용. "기관이 등록한 전자문서로 자동 발송" 은 어느 문서에서도 일어나지 않는다.
4. **감사장이 없다.** 감사 편지·감사장 전자문서, 연말·누적 도달 트리거, 프리셋 모두 없다. 기부금영수증 자동 발급도 MONTHLY 기관에 한정된다.
5. **자원봉사는 "모집" 이 없다.** 신청 이후만 있고, 모집 공고·모집 콘텐츠·일정·리마인드·활동 후 문서가 없다.
6. **후속 자동화를 꽂을 자리가 없다.** 이벤트 버스/저니 엔진이 없어 "후원 성공 → 감사 → 영수증 정보 안내 → N일 뒤 약정 권유 → 연말 영수증 → 감사장" 같은 체인을 선언할 수 없고, 매번 `charge-flow.ts` 를 고쳐야 한다.
7. **외부 연동이 전부 mock 이다.** PIN 인증(헥토 포함)·카드·알림톡·SNS OAuth/업로드·전자서명·지급대행·이메일. 코드 안에서는 어댑터 교체만 남았지만, 계약·심사가 끝나기 전까지 운영에서 "자동" 으로 보이는 건 문자 한 가지다.

### P1 — 발굴 구간 고도화

- **콘텐츠 캘린더/자율 생성**: 기관 설정에 `주 N건·요일·시간대·형식 비율` → 크론이 캠페인 상태(진행률·남은 기간)에 따라 자동 생성 → 자동 승인 통과 시 **자동 예약**(A6 해소). 월 한도·비용 상한은 기존 `monthlyLimit`·`costKrw` 로 제어.
- **카드뉴스 형식** `CARD_NEWS`(1:1 또는 4:5, 3~8장 세트) 추가 — 캠페인 `cardNews` 업로드본도 입력으로 사용.
- **기관 프로필 반영**: 소개·사업·로고(`avatarUrl`)를 brief 에 넣고 장면에 로고 삽입.
- **플랫폼별 변형**: 쇼츠 제목 100자, 인스타 캡션 2200자·해시태그 30, 페북 링크 우선 등 캡션 변형을 LLM 단계에서 생성.
- **플랫폼 확장**: `SocialPlatform` 에 `TIKTOK`, `NAVER_BLOG`, `KAKAO_CHANNEL`(채널 포스트) 추가 + 어댑터 자리. 틱톡은 Content Posting API 심사, 네이버는 블로그 API, 카카오 채널은 비즈메시지와 별개로 채널 포스트 API 가능 여부 확인(코드 밖).
- **성과 수집·학습**: `clicks` 를 `proxy.ts` 쿠키 설정 시점에 카운트, `metrics()` 실구현, 콘텐츠별 전환율 → 다음 생성의 톤·형식 선택에 반영(A/B).
- **댓글·DM**: 1차는 "새 댓글 알림 + LLM 답변 초안 → 승인" 범위로.

### P1 — 후원자 라이프사이클

- 결제 직후: 감사 문자에 **영수증 정보 등록 링크** 포함(정보성).
- 정기후원 정지(SUSPENDED) 후 **재개 안내**(결제수단 재등록 링크) 1회.
- 휴면(183일)·반복 일시후원자(`repeat_no_pledge`): 저니에서 **정보성 범위** 안의 안내만(연간 후원 요약 + 영수증 안내). 광고성 약정 권유는 본인이 '정기' 를 보낸 경우에만(기존 정책 유지).
- 기관 실시간 알림: `charge.paid` 이벤트 → 기관 인앱 알림 + (알림톡 승인 후) 담당자 알림톡.
- 캠페인 목표 달성: 자동 상태 전환 옵션 + 기관 알림 + 달성 감사 콘텐츠 자동 생성 트리거.
- `supporter_contact` 사후 역연결(첫 후원 시 phoneHash 로 명단 행 연결), 후원자 병합 도구(번호 변경·다계정, 관리자 승인·감사로그).
- 생년월일은 **수집하지 않는 것을 권장**(개인정보 최소화) — 대신 "첫 후원 1주년" 은 `payer_merchant_link.firstDonatedAt` 으로 가능.

### P1 — 자원봉사 완성

- **봉사 모집 공고** 개체(`volunteer_posting`: 활동·일정·장소·정원·모집 기간·필요 서류) + 모집 콘텐츠 유형(brief 에 봉사 필드) + 신청이 공고에 연결.
- 배정 구조화(슬롯·정원·출석), 상태 `COMPLETED/NO_SHOW` 추가.
- 저니: 승인 → D-1 리마인드 → 활동 기록 → **감사 문자 + 활동 확인서 자동 발급(기관 서식)** → 누적 N시간 감사장.
- F4 버그 수정: `issueVolunteerAgreement(applicationId, meta, { notify: true })`.
- 1365/VMS 는 CSV 유지(API 없음), 다만 양식 확정 시 열 매핑.

### P2 — 결제 수단 확장 (코드 밖 계약이 먼저)

- 카드 빌키(헥토 또는 별도 PG), 간편결제(카카오페이·네이버페이·토스 정기결제), 가상계좌 입금 통지 웹훅 대사(무통장 후원자용), 외부 CMS(효성·나이스) 출금동의 연동. 모두 `PaymentMethodKind`·`executePayment` 허브에 어댑터로 들어갈 수 있는 구조다.

### 운영·품질

- 크론 공통화(`runCronJob`), `webhooks` 잠금, 스케줄 정의 저장소 내.
- 감사로그 누락 보강: 봉사 승인/반려·활동 기록, 게시 예약/취소, AUTO 승인.
