# 외부 연동 설정 가이드 (2026-11-06, 고도화 7단계)

이 문서는 SNS 자동 게시(유튜브·인스타그램·페이스북·틱톡), 카카오 알림톡(솔라피), 메일(Amazon SES)을 실제로 켜기 위해 운영자가 해야 할 일을 정리한다. 코드는 공개 API 문서대로 구현했지만 **실제 키로 호출해 본 적은 없다**. 키를 넣은 뒤 스테이징에서 아래 "확인 순서"를 먼저 밟는다.

공통 원칙

- 키가 없는 공급자는 호출하지 않는다. 화면에는 "키 없음"으로 표시하고 성공을 꾸미지 않는다.
- 운영(`APP_ENV=prod`)에서 실공급자를 켰는데 필수 키가 비어 있으면 부팅이 거부된다(`integrationBootProblems`).
- 토큰·키 원문은 DB·로그·화면에 남기지 않는다. SNS 토큰은 `social_channel.access_token_enc / refresh_token_enc` 에 암호화해 둔다.
- 리디렉트 URI 는 모두 `${APP_BASE_URL}/api/studio/social/<platform>/callback` 이다. `<platform>` 은 `youtube`, `instagram`, `facebook`, `tiktok`.

## 1. SNS 공통

| 환경변수 | 설명 |
|---|---|
| `SOCIAL_PUBLISH_ENABLED` | 예약 게시 배치를 켠다 |
| `SOCIAL_PROVIDER` | `mock` 또는 `live`. `live` 이면 아래 키가 있는 플랫폼만 연결 버튼이 열린다 |
| `SOCIAL_OAUTH_STATE_SECRET` | OAuth state 서명 비밀(32바이트 이상 임의 값). 없으면 어떤 플랫폼도 연결을 시작하지 않는다 |

흐름: 기관 콘솔 `/studio/channels` → "계정 로그인으로 연결" → `GET /api/studio/social/<platform>/connect`(기관 담당자 세션 확인, state = 기관·플랫폼·nonce·만료 10분을 HMAC 서명, 구글은 PKCE) → 공급자 동의 화면 → `GET /api/studio/social/<platform>/callback`(서명·만료·플랫폼·세션 기관·브라우저 nonce 확인 → 코드 교환 → 계정 조회 → 암호화 저장 → 감사로그 `SOCIAL_CHANNEL_OAUTH_CONNECT`) → `/studio/channels?connected=<platform>`.

토큰 만료 5분 전부터 게시·지표 수집 때 리프레시 토큰으로 갱신한다. 갱신이 실패하면 채널이 `EXPIRED` 가 되고 기관에 인앱 알림이 간다. 기관은 같은 화면에서 "다시 연결"한다.

## 2. 유튜브 (구글)

1. Google Cloud Console 에서 프로젝트를 만들고 **YouTube Data API v3** 를 사용 설정한다.
2. OAuth 동의 화면: 앱 이름·지원 이메일·개인정보처리방침 주소·도메인을 등록하고, 범위에 `youtube.upload`, `youtube.readonly` 를 추가한다.
3. 사용자 인증 정보 → OAuth 클라이언트 ID → **웹 애플리케이션**. 승인된 리디렉션 URI 에 `${APP_BASE_URL}/api/studio/social/youtube/callback` 을 넣는다.
4. `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET` 을 넣는다.

검수·감사

- `youtube.upload` 는 민감 범위라 **OAuth 앱 인증(구글 검증)** 이 필요하다. 검증 전에는 테스트 사용자로 등록한 계정만 동의할 수 있고, 리프레시 토큰이 7일 뒤 만료될 수 있다.
- **YouTube API 서비스 규정 감사** 전에는 API 로 올린 영상이 비공개로 고정된다. 기브싸인은 항상 `privacyStatus=private` 로 올리고 결과를 `PRIVATE_UPLOADED`(비공개 업로드) 로 남긴다. 기관이 `/studio/content/[id]` 의 **"공개로 전환"** 을 누르면 `videos.update` 로 공개를 요청한다. 감사 전이면 유튜브가 거절하고 그 사유가 화면에 나온다.
- 업로드에 `status.containsSyntheticMedia=true`(AI 생성 표시)를 넣는다.
- 업로드 할당량: 기본 하루 10,000 단위, 업로드 1건 약 1,600 단위. 기관이 많아지면 할당량 증설을 신청한다.

제한: 숏폼 **영상 파일**이 있어야 올린다. 지금 콘텐츠 생성은 SVG 장면까지만 만들고 영상 조립 공급자가 없어서, 영상 주소가 없으면 게시가 "올릴 영상 파일이 없습니다" 로 실패한다(5단계가 `videoUrl` 을 채우면 그대로 동작).

## 3. 인스타그램·페이스북 (메타)

1. developers.facebook.com 에서 **비즈니스 유형** 앱을 만든다. "Facebook 로그인" 제품을 추가하고 유효한 OAuth 리디렉션 URI 에 `.../instagram/callback`, `.../facebook/callback` 둘 다 넣는다.
2. `META_APP_ID`, `META_APP_SECRET` 을 넣는다. `META_GRAPH_VERSION` 은 기본 `v26.0`(2026-07-29 출시, 2026-11 기준 최신). 버전이 만료되기 전에 올린다.
3. 기관 준비물: 인스타그램은 **비즈니스(또는 크리에이터) 계정 + 연결된 페이스북 페이지**, 페이스북은 페이지 관리자 권한.

요청 권한(앱 검수 대상)

| 플랫폼 | 권한 |
|---|---|
| 인스타그램 | `instagram_basic`, `instagram_content_publish`, `instagram_manage_insights`, `pages_show_list`, `pages_read_engagement`, `business_management` |
| 페이스북 | `pages_show_list`, `pages_read_engagement`, `pages_manage_posts`, `read_insights` |

검수 전 제한

- **앱 검수 전에는 메타 앱에 역할(관리자·개발자·테스터)이 있는 계정만** 연결·게시된다. 기관 계정으로 쓰려면 검수(화면 녹화·사용 설명)와 비즈니스 인증을 마쳐야 한다.
- 인스타그램은 계정당 24시간 50건까지 게시된다(배치가 한도를 넘기면 1시간 뒤로 미룬다).

동작

- 연결: 단기 사용자 토큰 → 장기 토큰(`fb_exchange_token`) → `/me/accounts` 의 페이지 토큰을 저장한다(만료 시각 없음, 리프레시 토큰 없음). 페이지가 여럿이면 **첫 번째 페이지**(인스타는 인스타 계정이 연결된 첫 페이지)를 쓴다 — 페이지 선택 화면은 아직 없다.
- 모든 호출에 `appsecret_proof` 를 붙이고, 토큰은 주소가 아니라 POST 본문으로 보낸다.
- 이미지: SVG 장면을 `sharp` 로 인스타그램은 JPEG, 페이스북은 PNG 로 바꿔 **공개 미디어 저장소**에 올린 주소를 넘긴다. 메타 서버가 그 주소를 가져가야 하므로 운영은 `STORAGE_DRIVER=s3` + 공개 주소(`S3_PUBLIC_BASE` 또는 공개 `APP_BASE_URL`)가 필요하다. 배포 이미지에 `sharp` 가 없으면 이미지 게시는 실패 사유로 남는다.
- 인스타그램: 1장 이미지 / 여러 장 캐러셀(최대 10) / 스토리 / 릴스(영상 필요). 페이스북: 사진 1장 `/photos`, 여러 장은 비공개 업로드 후 `/feed attached_media`, 영상 `/videos`(영상 필요).
- 지표: 인스타 `like_count` + insights `views`, 페이스북 반응 수 + insights `post_media_view`(지표 이름은 메타가 자주 바꾼다 — 실패하면 0 으로 둔다, 추정).

## 4. 틱톡

1. TikTok for Developers 에서 앱을 만들고 **Login Kit** 과 **Content Posting API**(Direct Post) 를 추가한다. 리디렉트 URI `.../api/studio/social/tiktok/callback`.
2. 범위: `user.info.basic`, `video.publish`, `video.upload`.
3. `TIKTOK_CLIENT_KEY`, `TIKTOK_CLIENT_SECRET` 을 넣는다.
4. `PULL_FROM_URL` 로 영상·사진을 가져가게 하므로 **미디어 주소 도메인(또는 URL 접두사) 소유 확인**을 개발자 콘솔에서 마친다.

감사 전 제한: 감사(audit)를 통과하기 전에는 **모든 게시가 비공개(나만 보기)** 로 묶인다. 기브싸인은 항상 `privacy_level=SELF_ONLY` 로 올리고 결과를 `PRIVATE_UPLOADED` 로 둔다(`is_aigc=true`). 게시는 비동기라 게시물 주소·지표는 아직 수집하지 않는다(`publish_id` 만 저장).

데이터 구조: 채널 저장 enum(`SocialPlatform`)에 `TIKTOK` 이 들어가야(5단계 마이그레이션) 연결이 열린다. 그 전에는 채널 화면에 "준비 중" 으로 표시된다.

## 5. 네이버 블로그 · 카카오톡 채널

- 네이버는 블로그 글쓰기 공개 API 를 종료했다. 카카오톡 채널 API 는 채널 추가·관계 조회·고객파일 관리만 제공하고 **채널 소식(포스트) 게시 API 가 없다**(2026-11 공식 문서 확인).
- 따라서 자동 게시를 구현하지 않았다. 채널 화면에 "공개 API 없음 — 내려받아 직접 게시" 로 안내한다. 공식 게시 API 가 나오면 `src/server/adapters/sns/platforms.ts` 의 `SNS_OAUTH_FAMILY` 부터 바꾼다.

## 6. 카카오 알림톡 (솔라피)

| 환경변수 | 설명 |
|---|---|
| `ALIMTALK_ENABLED` | 알림톡 사용 |
| `ALIMTALK_PROVIDER` | `coolsms`(솔라피) |
| `ALIMTALK_API_KEY` / `ALIMTALK_API_SECRET` | 비우면 문자 키 `MT_API_KEY` / `MT_API_SECRET`(같은 솔라피 계정)를 쓴다 |
| `SAFE_MODE` | `true` 이면 실제 알림톡을 막고 mock 으로 대체한다 |

준비

1. 솔라피 콘솔 → 카카오 → **발신프로필(채널) 연동**: 기관의 카카오톡 채널(비즈니스 인증 채널)을 연동하고 `pfId` 를 받는다. 기관 콘솔 `/studio/notices` 의 "발신프로필 키"에 이 `pfId` 를 넣는다.
2. **템플릿 등록·검수**: 기브싸인 정보성 템플릿(`ALIMTALK_TEMPLATES`) 본문과 **글자 하나까지 같은** 템플릿을 등록해 카카오 승인을 받고, 승인된 템플릿 ID 를 기관 콘솔의 템플릿 코드 칸에 넣는다. 광고성 템플릿은 만들지 않는다. 결제 링크·인증번호는 알림톡이 아니라 문자로만 보낸다.
3. 관리자 `/admin/automation` 에서 기관 채널을 확인 후 "사용 중(ACTIVE)" 으로 바꾼다.

동작: `POST https://api.solapi.com/messages/v4/send-many/detail`, 인증 `HMAC-SHA256 apiKey, date, salt, signature=hex(HMAC-SHA256(secret, date+salt))`, 본문 `type: 'ATA'`, `kakaoOptions: { pfId, templateId, disableSms: true }`, `text` 는 변수를 치환한 본문. 공급자 대체 문자를 끄고, 실패(`failedMessageList`·HTTP 오류)하면 기브싸인이 같은 본문을 문자로 보내고 `mt_outbound_message.fallback=true` 로 남긴다. 접수(2000)는 카카오 전달 완료가 아니다(리포트 수신은 미구현).

EMMA(인포뱅크) 알림톡은 알림톡 큐 테이블 규격을 받지 못해 구현하지 않았다(`ALIMTALK_PROVIDER=emma` 는 운영 부팅에서 거부).

## 7. 메일 (Amazon SES)

| 환경변수 | 설명 |
|---|---|
| `MAIL_PROVIDER` | `mock` 또는 `ses` |
| `MAIL_FROM` | SES 에서 인증한 발신 주소 |
| `SES_REGION` | 비우면 `AWS_REGION` |
| `SES_ACCESS_KEY_ID` / `SES_SECRET_ACCESS_KEY` | 비우면 `AWS_ACCESS_KEY_ID` / `AWS_SECRET_ACCESS_KEY`(+`AWS_SESSION_TOKEN`) |

준비

1. SES 콘솔(같은 리전) → **확인된 자격 증명**에서 발신 도메인(예: `givesign.kr`)을 등록하고 DKIM CNAME 3개를 DNS 에 넣는다. SPF·DMARC 레코드도 설정한다. 사용자 지정 MAIL FROM 도메인을 권장한다.
2. **샌드박스 해제(프로덕션 액세스 요청)**: 샌드박스에서는 확인된 주소로만 보낼 수 있고 하루 200통 제한이 있다. 용도(비밀번호 재설정·이메일 인증·발급 문서 안내, 광고 없음)와 반송·수신 거부 처리 방법을 적어 요청한다.
3. IAM 사용자(또는 키)를 만들고 `ses:SendEmail` 만 허용한다. 작업 역할(ECS/EC2 메타데이터) 자격 증명은 이 구현이 읽지 않으므로 키를 환경변수로 넣는다.

동작: SES v2 `POST https://email.<region>.amazonaws.com/v2/email/outbound-emails` 를 SigV4(서비스 `ses`)로 직접 서명한다(서명 대상 헤더 `content-type;host;x-amz-content-sha256;x-amz-date`). 메일이 실연동(ses + 필수 설정)일 때만

- 비밀번호 재설정: 링크를 메일로만 보낸다(콘솔·로그·화면에 남기지 않는다). 화면 문구 "재설정 링크를 메일로 보냈습니다".
- 후원 회원 가입: 이메일 인증 링크(24시간, 1회용, 해시 저장)를 보낸다. `/donate/<코드>/verify-email?token=` 으로 확인하면 `donor_member.email_verified_at` 이 채워진다.

mock 이면 지금처럼 메일을 보내지 않고 문구도 바꾸지 않는다. 발급 문서 안내 메일 함수(`sendDocumentMail`)는 만들어 두었고 영수증·약정서 자동 발송 단계에서 연결한다.

## 8. 확인 순서 (스테이징)

1. 관리자 `/admin/automation` 상단 타일에서 각 공급자가 "실연동" 인지(키 없음이면 빠진 변수 이름이 보인다) 확인한다.
2. 앱 역할이 있는 테스트 계정으로 `/studio/channels` 에서 플랫폼별 연결 → 채널 카드가 "연결됨" 인지 확인한다.
3. 승인된 캠페인 이미지 1건을 페이스북 테스트 페이지로 예약 → `/api/cron/content` 실행 → 게시물 링크 확인.
4. 기관 알림톡 채널을 ACTIVE 로 두고 정기후원 시작 안내 1건 → 솔라피 콘솔에서 접수·전달 확인.
5. 비밀번호 재설정을 확인된 수신 주소로 요청해 메일 도착을 확인한다.

## 규격·계약 수령 후 (이번 단계에서 손대지 않음)

헥토 PIN 인증창(`adapters/payment/hecto.ts`), 지급대행(`adapters/payout`), 카드 PG, 본인인증, 외부 전자서명 공급자, EMMA 알림톡.
