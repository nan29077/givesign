- 위치: `src/server/services/edoc.ts:674-692`(서명), `479-483`(취소), `730`(거절)
- 내용:
  ```ts

  ...

  const all = await tx.eDocSigner.findMany(...);
  if (all.every((x) => x.status === 'SIGNED')) {
  ```

  `claimed` 의 봉투 상태 검사는 READ COMMITTED 스냅샷에서 취소 트랜잭션 커밋 전에 통과할 수 있고, 이후 `appendEvent` 의 FOR UPDATE 가 취소 커밋을 기다린 뒤 조건 없는 `update` 로 COMPLETED 를 쓴다. `declineAsSigner` 의 `eDocEnvelope.update({ status: 'DECLINED' })` 도 같다(만료 배치의 EXPIRED 를 덮을 수 있음).
- 영향: 기관이 취소한 문서가 "서명 완료"로 바뀌고 완료 문자가 발송된다. 창은 좁지만 상태 기계 정합성 결함. (환원은 서명자가 열기 전만 가능하므로 금액 중복 환원은 없음.)
- 수정 제안: 봉투 잠금(`appendEvent` 앞에 `SELECT ... FOR UPDATE`) 뒤 상태를 다시 읽어 OPEN 이 아니면 `EDocError` 로 롤백하고, 완료·거절 전이도 `updateMany({ where: { id, status: { in: OPEN_STATUSES } } })` 로 조건부 갱신한다.
- 확신도: 확인됨(로직) / 발생 빈도는 추정

## 점검했으나 문제 없음(기록)

- 토큰 비교: 해시 유일 인덱스 조회(`findUnique tokenHash`)라 문자열 비교 타이밍 문제 없음. 접근 증표·OTP 는 `safeEqual`.
- OTP: 5회 오입력 시 코드 삭제, 30분 5건 발송 제한, 코드는 HMAC 저장, 재발송 시 증표 자동 무효(현재 `tokenHash` 에 묶임).
- 다른 봉투·서명자 데이터 노출: 서명자 화면은 자기 봉투의 마스킹 값·같은 봉투 공동 서명자 서명 이미지만. 기관 콘솔 조회는 모두 `merchantId` 조건. 템플릿·봉투 IDOR 없음.
- `signBasePdf` 검증: 미리보기·등록 두 경로 모두 검증(`resolveBase`, `applyPdf`), 저장된 서식은 `templateId+merchantId`.
- 업로드: 매직바이트·크기·확장자 화이트리스트, 저장 이름 무작위, `/api/media` 경로 정규식, 글꼴 확장자 미서빙(로컬 드라이버 기준).
- 원장: 멱등키 `use:/refund:/topup:/bonus:/plan:/expire:/adjust:/trial:` 모두 존재, 차감 순서 `pickUseSource`, FOR UPDATE, 취소 환원 조건(`viewedAt`·`otpVerifiedAt`), 만료·거절 미환원, `verifyWallet` 집계식 정확, `splitVat` 반올림(공급가=round(총액/1.1)) 일관, `effectiveFrom <= now` 최신 1건 선택, 지난 요금제 삭제 불가.
- 스냅샷: 결과 PDF 는 항상 새 이름으로 저장(`renderAndStore`), 어디서도 삭제·덮어쓰기 없음. 스냅샷 `pdfUrl/pdfHash` 는 `renderedPdfUrl ?? basePdfUrl` 로 발송 시점 고정.
- 좌표계: 편집기는 `convertToPdfPoint/convertToViewportPoint`(CropBox 오프셋·회전 반영), 서버는 사용자 좌표 그대로 `Tm` — 위치는 일치(회전 시 방향만 위 중간 항목).
- strip 의 글자 적중 판정(진행 방향 절반·0.35em)과 덮개 범위(-0.26~0.95em·0.05em 패딩)로 인접 줄·인접 글자 오삭제 경로는 찾지 못했다(폭을 모르는 경우는 위 높음 항목).
- pdf.js 는 `legacy/build` + 같은 출처 워커, 서버 PDF 파싱 예외는 `convert.ts`·`renderAndStore` 에서 잡힘(미리보기 경로만 위 낮음 항목).
- 화면 문구: 공동인증서·공인전자문서중계·TSA 미연동 고지가 서명 화면·확인서·기관·관리자 화면에 모두 있음. 문자 발송 결과는 실제 어댑터 결과(`sent.ok`)로만 "보냈습니다" 를 표시.
