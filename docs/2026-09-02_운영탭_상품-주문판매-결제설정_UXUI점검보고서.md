## 0. 한 장 요약

지금 운영 탭은 **"기능은 대부분 있는데, 일반적인 판매 관리자에서 기대하는 모양이 아니다"** 는 상태입니다.

| 구분 | 지금 | 문제의 성격 |
|---|---|---|
| 상품 설정 | 한 화면에 목록+등록폼을 모두 펼친 구조, 필드 나열식 | 일반 커머스 상품등록 폼(섹션형·목록/상세 분리)과 다름 |
| 주문·배송 | 실물만 다룸. 비실물 판매는 '후원 내역'에 섞여 있음 | 판매 관리의 절반이 메뉴에 없음 |
| 결제 설정 | 탭 7개 중 3개가 사실상 읽기 전용, 1개는 상품설정과 중복 | 메뉴 이름과 내용 불일치 |

그리고 **기능 결함 3건**(다음 항목)은 UI 개편과 별개로 먼저 고쳐야 합니다.

1. 상품 이미지가 저장되지만 구매자 화면에 **한 번도 표시되지 않음** (폼 안내문은 "결제 화면에 보여집니다"라고 잘못 안내)
2. 주문·배송 목록이 배송지(이름·전화·주소) **원문을 전 건 자동 복호화**해서 뿌림 — 마스킹 컬럼과 감사로그 설계가 있는데 사용하지 않음
3. 실물 주문이 **'포인트 지급 대기'에 섞여** 후원 내역과 파트너 API에 올라옴

## 2. 상품 설정

### 2-1. 지금 구조

`상품 설정` 안에 탭 3개 — **비실물 상품 / 실물 상품 / 배송 정책**.
각 탭은 `[통계 4칸] → [등록된 상품 카드들(각 카드가 곧 수정 폼)] → [맨 아래 추가 폼]` 순서입니다.

즉 **목록과 편집 폼이 같은 화면에 겹쳐 있고, 상품 개수만큼 폼과 저장 버튼이 생깁니다.** 상품이 10개면 저장 버튼이 11개(수정 10 + 추가 1)입니다.

### 2-2. 일반적인 실물 상품 등록 폼과의 차이

셀러 어드민 계열(셀러브릭스·카페24·고도몰 등)의 **실물 상품 등록(간편등록 아님)** 폼은 보통 이렇게 섹션이 나뉩니다. 현재 구현과 대조하면:

| 일반 폼의 섹션 | 항목 | 기브싸인 현재 |
|---|---|---|
| ① 기본 정보 | 판매상태, 상품명, 상품코드(SKU), 카테고리, 노출순서 | 있음 (카테고리 없음) |
| ② 판매 정보 | 판매가, 할인가, **과세구분**, 재고, 최소/최대 구매수량 | 판매가·재고·최대수량만. **과세구분·할인 없음** |
| ③ 옵션 | 조합형/단독형, **옵션별 추가금·재고·품절** | 자유 텍스트 3줄뿐. 옵션별 재고·추가금 **불가** |
| ④ 이미지 | **대표 이미지(필수)**, 추가 이미지, 상세 이미지 | 등록 폼에만 1장. **수정 폼엔 이미지 칸 자체가 없음** |
| ⑤ 상세 설명 | 에디터(HTML/이미지) | 300자 textarea |
| ⑥ 배송 정보 | 배송비 유형, 도서산간, **출고 소요일, 반품·교환 배송비, 반품지 주소** | 배송비/조건부무료/무료배송만. **반품 관련 전무** |
| ⑦ 상품정보 제공 고시 | 전자상거래법 품목별 필수 고지 | **없음** |
| ⑧ 노출/검색 | 태그, 진열 여부 | 노출 체크박스만 |

**빠진 것 중 법적으로 문제가 되는 것**: ⑦ 상품정보 제공 고시, ⑥ 반품·교환 배송비와 반품지, 청약철회 안내. 실물 상품을 파는 이상 전자상거래법상 필요합니다.

### 2-4. 제안 — 등록 폼 개편안

**공통**: 목록과 등록/수정을 **분리**합니다. `후원 항목 관리` 목록(표) → 행 클릭 시 `/studio/products/[id]` 상세 편집, `+ 상품 등록` 버튼 → `/studio/products/new`. 목록에는 이미지 썸네일·상품명·유형·판매가·재고·상태·판매건수, 그리고 체크박스 선택 후 **일괄 노출/숨김·보관**.

**실물 상품 등록 폼 (섹션형)**

1. 기본 정보 — 판매 상태, 상품명, 상품코드(SKU), 노출 순서
2. 판매 정보 — 판매가, **과세 구분(과세/면세)**, 재고, 재고 경고 기준, 1회 최대 수량
3. 옵션 — 옵션 없음 / 단독형 / 조합형. 옵션값마다 **추가금·재고·품절** 입력
4. 이미지 — 대표 이미지(필수), 추가 이미지 최대 5장, 상세 이미지
5. 상세 설명
6. 배송 정보 — `기본 정책 따름` / `이 상품만 개별 설정` 토글, 배송비 유형(무료·유료·조건부무료), 도서산간, **출고 소요일**, **반품/교환 배송비**, **반품지 주소**
7. **상품정보 제공 고시** — 품목 선택 후 필수 항목 입력
8. 우측 고정 패널에 **실시간 결제금액 시뮬레이션**(현재의 "1개 주문 시 결제 금액" 박스를 폼 안으로) + **구매자 화면 미리보기**

**비실물(컨텐츠) 상품 등록 폼**

1. 기본 정보 — 유형(포인트 / 상품권 / 이용권 / **컨텐츠**), 상품명, 상품코드, 노출 순서, 판매 상태
2. 판매 정보 — 판매가, 지급 수량·단위, 유효기간(일)
3. **지급 방식** — `사회복지기관 수동 지급` / `연동 API 자동 지급` / `즉시 발급(코드·다운로드 링크)`. 지금은 수동 + API pull만 가능하고 화면에서 고를 수 없음
4. 이미지·상세 설명
5. **청약철회 안내** — 디지털 콘텐츠 특례(사용 개시 시 철회 제한) 고지 문구
6. 미리보기

> 표기 규칙: 화면 문구는 **「비실물(컨텐츠)」** 로 통일. 유형 선택지도 포인트/상품권/이용권/컨텐츠 4종으로.

## 3. 주문·배송 → 「후원 처리」

### 3-1. 명칭

요청하신 대로 **"주문·배송" → "후원 처리"** 로 바꾸고 안에서 둘로 나누는 것이 맞습니다.

```
후원 처리
 ├ 실물 주문·배송     (지금의 orders)
 ├ 비실물(컨텐츠) 판매내역  (지금 '후원 내역'에 섞여 있는 지급 처리)
 └ 반품·교환          (신설)
```

지금은 비실물 판매를 관리할 전용 화면이 없고, `후원 내역`의 "포인트 지급 대기" 패널로 처리합니다. 상품 설정에서는 실물/비실물을 나눠 놓고 판매 관리에서는 안 나뉘어 있는 게 가장 큰 비대칭입니다.

### 3-2. 발견 사항 (주문·배송)

### 3-3. 제안 — 고도화 항목

**실물 주문·배송 탭**

- 상단: 기간 + 상태 + 통합검색(거래번호·받는분·송장·상품명) + 정렬 선택
- 목록 기본은 **마스킹**(홍*동 / 010-****-1234 / 서울 강남구). 행의 `[배송지 보기]`를 눌러야 원문 노출 + 감사로그 기록
- 체크박스 선택 → **일괄 발송 처리**, **송장 일괄 등록**(택배사 선택 + 거래번호·송장 붙여넣기)
- **주문서 엑셀 내려받기** / 송장 엑셀 업로드
- 발송 처리 시 구매자에게 **발송 안내 문자** 발송(옵션 토글)
- 상태에 `반품접수 / 회수중 / 반품완료 / 교환접수 / 교환발송` 추가
- "결제 후 2일 이상 미발송" 지연 경고 타일

**비실물(컨텐츠) 판매내역 탭**

- 지금 후원 내역에 있는 지급 대기/완료/보류 처리를 이쪽으로 이동
- 상품별·유형별 필터(포인트/상품권/이용권/컨텐츠)
- 지급 완료 시 구매자 알림, 지급 취소(회수) 처리
- 유효기간 있는 상품의 만료 임박 목록

**결제 상세 화면(`charges/[id]`)에 주문 정보 블록 추가** — 상품명·수량·옵션·상품금액·배송비·배송상태·송장. O-10 해소.

## 4. 결제 설정 — 탭별 정밀 점검

현재 탭 7개: `결제 금액 / MO 안내문자 / 감사문자 / 결제 모드 / 문자번호 / 결제페이지 / 연동 API`.
이 중 **완전 읽기 전용이 2개(결제 모드·문자번호)**, **절반이 읽기 전용인 것이 1개(결제 금액)** 입니다.

### 4-1. 결제 금액 탭 — 이름과 내용이 다름

| 문제 | 상세 |
|---|---|
| 이름-내용 불일치 | "결제 금액" 탭에서 금액을 정할 수 없음. 실제 금액은 상품 설정에서 정함 |
| 중복 | 상품 목록이 읽기 전용으로 한 번 더 나옴. 상품 설정과 이중 관리 |
| 오해 소지 | 실물 상품 금액을 **배송비 없이** 표시. 실제 결제액과 다름 |
| 기능 부족 | 직접 입력 허용 시 사회복지기관이 **자체 상·하한이나 입력 단위(1,000원 단위 등)를 정할 수 없음**. 플랫폼 정책 범위 그대로 |
| **코드 결함** | `createChargeProductAction`, `updateChargeProductAction`, `archiveChargeProductAction` 3개가 **import만 되고 미사용**. ESLint 경고 3건 확인. 예전에 이 탭에서 상품을 등록하던 흔적 |

### 4-2. MO 안내문자 탭 — 검증은 튼튼, 안내는 부족

- 좋은 점: 160자 제한 / 링크 금지 / 미정의 치환자 금지 / 금칙어·개인정보 필터, **현재 설정 미리보기 + 기본 문구 비교**, "아직 결제되지 않았습니다" 고지를 시스템이 강제로 붙인다는 설명. 감사문자와의 차이를 상단 Notice로 설명하는 것도 좋음.
- 지적:
  - 저장 검증이 **템플릿 원문 160자**만 봄. `{상품목록}`은 상품명 4개까지 치환되므로 **치환 후 실제 발송 길이는 검사하지 않음**. 사회복지기관명·상품명이 길면 SMS→LMS로 넘어가 발송 단가가 달라짐. 미리보기 옆에 **"치환 후 N자 · SMS/LMS 구분"** 표시 필요
  - **테스트 발송 버튼이 없음**. 저장 후 실제 문자를 자기 번호로 받아볼 방법 없음
  - 치환자를 클릭해서 본문에 삽입하는 기능 없음(눈으로 보고 직접 타이핑)

### 4-3. 감사문자 탭

- MO 안내문자와 같은 수준으로 잘 검증됨(링크·개인정보 금지, 미리보기, 기본 문구 비교).
- 지적: 테스트 발송 없음 / 발송 실패 건의 재발송 경로 없음 / MO 안내문자 탭과 화면 구조가 거의 같아 **두 탭을 하나로 합쳐 섹션 2개로 두는 편이 이동이 적음**.

### 4-4. 결제 모드 탭 — 탭 하나를 쓸 내용이 아님

- 전부 읽기 전용(확인형/즉시형 설명 + 플랫폼 허용 여부 + 안내 Notice).
- 사회복지기관이 할 수 있는 행동이 0. **문자번호 탭과 합쳐 "수신·결제 방식(읽기 전용)" 한 탭**으로 충분.

### 4-5. 문자번호 탭

- 읽기 전용. 수신번호/수신방식/키워드/상태만.
- 지적: 키워드형인 경우 **후원자에게 안내할 문구를 복사하는 버튼이 없음**(예: `1600-0000 으로 '충전' 전송`). 번호 복사 버튼도 없음.

### 4-6. 결제페이지 탭

| # | 내용 |
|---|---|
| S-1 | 섹션 설명에 **"배너·소개·라이브 표시를 관리합니다"** 라고 되어 있으나 라이브 표시 필드가 없음 — 옛 후원 서비스 잔재 문구 |
| S-2 | 배너 라디오 기본 선택 로직이 `bannerUrl == null` 이면 자동 배너를 선택된 것처럼 보여줌. 그대로 저장하면 자동 배너가 **고정 값으로 굳음**. "자동(기본 배너)" 선택지가 명시적으로 없음 |
| S-3 | **미리보기 없음.** 저장 후 `/c/{코드}` 를 새 탭으로 열어봐야 함 |
| S-4 | 상품이 결제페이지에서 어떻게 보이는지 여기서 확인 불가 (상품 설정에도 없음 — 미리보기가 어디에도 없음) |

### 4-7. 연동 API 탭

- 좋은 점: "키 원문은 발급 직후 한 번만 표시" 경고가 명확, 폐기 확인창, 마지막 사용 시각 표기, 이 API가 필요한 경우를 먼저 설명하는 구성.
- 지적:
  - 규격서를 "고객센터로 요청"하라면서 파일 경로(`docs/연동규격서_사회복지기관API.md`)를 그대로 노출 — **문서 페이지 또는 다운로드 링크**가 필요
  - 키별 **권한 범위·IP 허용목록** 없음
  - **최근 호출 로그/에러가 안 보임**(lastUsedAt만) — 연동 디버깅 불가
  - `GET /ping` **연결 테스트 버튼**이 화면에 없음

### 4-8. 제안 — 메뉴 통합안

요청하신 "상품설정·주문배송·결제설정을 합칠 수 있으면 합치자"에 대한 답은 **"완전 통합보다는 3개를 판매 업무 흐름대로 재배치"** 입니다. 세 메뉴를 한 페이지에 합치면 탭이 12개 이상이 되어 오히려 나빠집니다.

```
운영  →  판매

  후원 항목 관리        목록 / 등록·수정 (실물 · 비실물(컨텐츠))
  후원 처리        실물 주문·배송 / 비실물(컨텐츠) 판매내역 / 반품·교환
  후원 설정        결제·금액 / 배송 정책 / 안내 문자 / 결제페이지 / 연동 / 수신·결제 방식(읽기전용)
  금칙어·차단
  신고
```

핵심 이동 3가지:

1. **배송 정책**: 상품 설정 → 후원 설정 (배송 업무를 한 곳으로)
2. **MO 안내문자 + 감사문자**: 두 탭 → `안내 문자` 한 탭에 섹션 2개
3. **결제 모드 + 문자번호**: 두 탭 → `수신·결제 방식` 한 탭 (읽기 전용끼리)
4. **결제 금액 탭의 상품 목록 블록 삭제**, 직접입력·한도·(신설)입력 단위만 남김

결과: 결제 설정 7탭 → 후원 설정 6탭, 읽기 전용 탭 2개 → 1개, 상품 목록 중복 제거.

## 7. 결정이 필요한 사항

개발 지시 전에 정해 주셔야 하는 것들입니다.

1. **옵션 구조화 범위** — 조합형 옵션(사이즈×색상별 재고·추가금)까지 갈지, 단독형(옵션값별 추가금만)에서 멈출지. 조합형은 `ChargeProduct` 아래 variant 테이블이 추가로 필요합니다.
2. **사회복지기관 환불 권한** — 사회복지기관이 직접 환불을 실행하게 할지, 환불 "요청"만 만들고 관리자 승인을 거치게 할지.
3. **상품 상세 설명** — 300자 텍스트를 유지할지, 이미지가 들어가는 에디터로 갈지(업로드 용량·XSS 처리 범위가 달라집니다).
4. **메뉴명 확정** — "후원 처리" / "판매 관리" / "주문 관리" 중 어느 것으로 할지.
5. **비실물 4번째 유형** — 기존 POINT/VOUCHER/PASS에 `CONTENT`를 추가할지, 아니면 화면 표기만 "비실물(컨텐츠)"로 하고 유형은 3종 유지할지.
