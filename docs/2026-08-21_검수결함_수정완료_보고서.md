## 1. 원천징수 계산 — 국내 표준 방식 적용

지시하신 대로 실무 표준으로 바꿨습니다. 3.3% 를 한 번에 곱해 절사하던 것을 **2단계**로 나눴습니다.

```
1) 소득세     = 지급액 × 3%   → 10원 미만 절사   (국고금관리법 제47조)
2) 지방소득세 = 소득세 × 10%  → 10원 미만 절사
3) 합계       = 소득세 + 지방소득세
4) 소액부징수 : 소득세가 1,000원 미만이면 전액 미징수 (소득세법 제86조)
```

**예시**

| 정산액 | 소득세 | 지방소득세 | 원천징수 | 실지급 | (기존 3.3%) |
|---|---|---|---|---|---|
| 333,333원 | 9,990 | 990 | **10,980** | 322,353 | 10,999 |
| 1,000,000원 | 30,000 | 3,000 | **33,000** | 967,000 | 33,000 |
| 30,000원 | 0 | 0 | **0** (소액부징수) | 30,000 | 990 |

**실무상 바뀌는 점 하나**: 소액부징수 때문에 **정산액 33,334원 미만은 원천징수 없이 전액 지급**됩니다. 법대로입니다.

소득세·지방소득세를 **각각 DB 컬럼에 저장**하도록 바꿨습니다(`income_tax`, `local_tax`). 지급명세서는 둘을 따로 적어야 해서 합계만으로는 신고서를 만들 수 없습니다. 원천징수 CSV에도 두 열이 분리돼 나갑니다.

> 세액 최종 확정은 세무 자문을 거치시길 권합니다. 저는 세무 전문가가 아닙니다.

## 2. 치명 4건

### CRIT-1. 결제 결과 미확인(UNKNOWN) 보존
`donation-flow.ts` — 승인 여부를 확인 못 한 건을 즉시 `FAILED` 로 덮어쓰던 것을 **UNKNOWN 그대로 유지**하도록 바꿨습니다. 함께 처리한 것:

- 실패 문자를 보내지 않습니다 (돈은 나갔는데 "실패" 안내가 가면 이중청구 오해를 부릅니다)
- 실패 카운터를 올리지 않습니다 (정상 후원자가 잠기던 문제)
- 후원 상태를 `PENDING_PAYMENT` 로 유지하고 사유만 남깁니다
- **`RiskDetection(PAYMENT_UNKNOWN, CRITICAL)` 을 생성**해 관리자 큐에 올립니다. 같은 건이 중복 등록되지 않도록 미해결 건이 있으면 건너뜁니다
- 후원자에게는 "결제 결과를 확인하는 중입니다"로 안내합니다

이제 `/admin/payments` 의 "확인 필요" 큐가 실제로 채워져 수동 대사가 가능합니다.

### CRIT-2·3. 민감정보 CSV 접근통제
- 주민등록번호 CSV / 계좌·실명 CSV 모두 **화이트리스트(`SUPER_ADMIN`·`FINANCE`)** 로 전환. 기존 블랙리스트 방식은 `AdminPermission` 기본값이 `READ_ONLY` 라 그대로 뚫려 있었습니다
- 다운로드마다 **감사로그 기록**: 누가·언제·몇 건·주민번호 원문이 몇 건 포함됐는지
- 미인증 요청은 500 대신 **401** 로 정리

### CRIT-4. MO 번호 라우팅 충돌
세 겹으로 막았습니다.

1. **DB**: `CREATE UNIQUE INDEX ... ON creator_mo_number(phone_number) WHERE keyword IS NULL` 부분 유니크 인덱스 — PostgreSQL 이 NULL 을 서로 다른 값으로 취급해 전용번호가 무제한 중복되던 구멍을 막습니다(같은 파일의 `banned_word` 가 이미 쓰던 방식과 동일)
2. **등록**: 같은 번호에 전용/대표번호 모드를 섞어 등록할 수 없습니다. 전용번호는 키워드를 붙이지 않도록 정규화
3. **라우팅**: 그래도 충돌 상태가 남아 있으면 **아무에게도 배달하지 않고** 관리자 로그를 남깁니다. 엉뚱한 사회복지기관에게 돈이 흘러가는 것보다 접수 실패가 낫습니다

3. **DB 롤 분리** — SQL은 가이드에 넣었지만 실제 실행은 RDS 생성 시점에 해야 합니다.
4. **쿠콘 연동규격서** — 이체파일 열 순서는 표준형입니다. 규격서를 받으시면 헤더만 대조하면 됩니다.
