## 전자문서

- 참고 서비스: https://www.paysign.co.kr/
- 소개: `/electronic-documents`, 메인에 서식·업무 흐름·이용 방식 소개 추가.
- 기관 센터: `/studio/e-documents`.
- 서식 편집·업로드·제출 확인: `/studio/documents`.
- 기관 이용 잔액·신청·사용 이력: `/studio/document-billing`.
- 관리자 요금·입금 확인·기관 이용 현황: `/admin/e-documents`.
- 기본 서식: 후원약정서, 자원봉사 신청서, 현물 기부 신청서, 프로그램 참여 신청서, 개인정보 동의서.
- 기부금영수증은 `/studio/receipts`의 검증된 실적·기관 자격·발급번호 체계를 그대로 사용. 일반 서식으로 임의 영수증을 만들지 않음.
- 후원 결제 없이 수신인별 작성 요청을 발급. 링크 원문은 한 번만 표시하고 DB에는 해시만 저장.
- 수신인·제출값과 요청 당시 서식 스냅샷을 암호화. 스냅샷 SHA-256 확인값과 제출 시각·접속정보, 원문 열람 감사기록 유지.
- 요청 생성·이용량 차감·사용 이력 저장은 같은 트랜잭션으로 처리. 같은 요청 키의 중복 생성·중복 차감을 방지.
- 제출은 한 번만 가능하며 제출 뒤 수정 불가. 기관 확인 완료와 인쇄·브라우저 PDF 저장 지원.

## 충전형·정액형

- 초기 예시 설정: 요청당 200원, 30일 정액 30,000원/200건, 신규 시범 5건. 최고관리자가 실제 요금·제공량으로 변경할 수 있음.
- 차감 순서: 유효 정액 제공량 → 시범 잔여량 → 충전 잔액.
- 작성 요청 생성 시 1건 차감. 재열람·제출·기관 확인에는 추가 차감하지 않음.
- 충전·정액 신청만으로 결제 성공이나 잔액 증가를 처리하지 않음.
- 관리자가 실제 입금·계약을 확인한 뒤 승인하며 같은 신청을 두 번 반영할 수 없음.
- 정액 유효기간은 승인 시점부터 30일. 자동 출금·자동 갱신은 실행하지 않음.
- 전자문서 서비스 이용 잔액은 후원금과 별개. 기존 후원·정산 원장은 변경하지 않음.
- 공인 본인인증·TSA·카카오 인증서·공인 전자문서 유통증명은 연동 전. 내부 자필서명·감사기록을 공인 인증으로 표시하지 않음.

## 검증

- 타입 검사와 소스 린트.
- 격리된 메모리 DB에서 전체 테스트 459건 통과, 2건 환경 조건으로 제외.
- 제외 중 정기후원 동시 약정 생성 1건은 PGlite가 여러 독립 트랜잭션을 단일 백엔드에 다중화하므로 실제 PostgreSQL에서 계속 검증하도록 구분. 이 검사는 PostgreSQL 환경에서는 실행됨.
- 브라우저: 기관 이미지 선택 저장·재조회, 문서 링크 발급·제출·기관 확인 완료, MO 표기 및 관리자 디자인 설정 확인.
- 로컬 브라우저 검수 문서는 이름에 '검수'를 표시했으며 실제 문자·외부 결제를 수행하지 않음.
