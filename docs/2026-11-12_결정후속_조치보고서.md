- 예시 문장은 카드에 들어가지 않고, 저장 차단 검사(작성 안내 문구)에도 걸리지 않는 문장으로 썼다(테스트).
- 같이 고침: 안내 문장 사이 띄어쓰기 누락("저장됩니다.본문을").

### 4) 개발 도구 취약점
- 원인: 린트 도구 typescript-eslint 가 쓰는 minimatch 10.x(서비스 거부 공지, 중간).
- eslint 10 으로 올리는 안은 Next 린트 묶음의 react·import·접근성 플러그인이 아직 eslint 10 을 지원하지 않아(플러그인 요구 버전 확인) 깨진다. 그래서 eslint 9 를 유지하고 `package.json` `overrides` 로 그 경로의 minimatch 만 수정판 11.0.8 로 고정했다.
- 결과: `npm audit` 전체 0건(운영·개발 모두), eslint 경고 0. npm 10(`npm ci`)과 npm 11 모두 설치 확인.
- 나중에 플러그인이 eslint 10 을 지원하면 이 고정을 지우고 올리면 된다(규칙 문서에 적어 둠).

### 5) 영상 재조립을 요청 밖으로
**전**: 담당자가 숏폼 자막을 고쳐 저장하면 그 요청 안에서 MP4 를 다시 조립(장면 6개 기준 수십 초) — 그동안 화면이 멈춘 것처럼 보이고, 서버 시간 제한에 걸리면 저장 자체가 실패할 수 있었다.

**후**:
1. 저장은 장면·캡션을 바꾸고 예전 영상을 비운 뒤 **재조립 작업만 쌓는다**(`content_job` 의 `REASSEMBLE` 단계, 장면 지문 포함). 저장 응답 1.8초(실측).
2. 실행은 세 곳이 나눠 맡는다 — 저장 응답을 보낸 직후(`after()`), 1분 배치(`/api/cron/events`, 45초 상한), 1시간 배치(`/api/cron/content`). 실측 21초 뒤 영상 준비.
3. 상세 화면은 "영상 준비 중"을 보이고 5초마다 저절로 새로고침해 영상이 나타나면 멈춘다. 준비 중에는 승인 버튼 대신 "영상 준비가 끝나면 승인할 수 있습니다".
4. **준비 중 승인은 서버에서도 거절**한다(주간 일괄 승인도 같은 함수라 "영상을 다시 만드는 중" 이유와 함께 건너뜀). 승인 때 예약이 영상 없는 숏폼을 건너뛰어 게시가 빠지는 일을 막는다.
5. 경합: 조립하는 사이에 담당자가 다시 고치면, 마무리 단계에서 작업 행을 잠그고 지문을 비교해 **옛 장면 영상은 버리고** 다음 실행이 새 장면으로 만든다.
6. 실패: 예외는 3회까지 다시 시도 후 "다시 만들지 못했습니다"(자막을 다시 저장하면 새로 시도). 조립 도구가 꺼진 환경(영상 미생성)은 예전처럼 영상 없이 닫고 승인을 막지 않는다 — 영상 없는 숏폼의 예약 차단은 기존 규칙 그대로.
- 마이그레이션 없음(기존 `content_job` 표 사용). 처음 생성 과정(대본→장면→조립)은 바꾸지 않았다.
- 운영 메모: 응답 뒤 실행이 서버 재시작 등으로 끊겨도 1분 배치가 이어 만든다. 1분 배치(`/api/cron/events`)는 이미 등록 대상이라 새로 등록할 배치는 없다.

## 3. 영향 범위 점검 (다른 기능에 문제가 없게)
- 영상 재조립 변경은 숏폼 수정 경로만 바꿨다. 카드뉴스·피드 수정은 예전과 같다(테스트). 처음 생성 단계 기록(`ASSEMBLE`)과 생성 재개 로직은 손대지 않았다.
- 승인 거절 조건은 "숏폼 + 재조립 대기·진행 중"일 때만 — 재조립 기록이 없는 기존 콘텐츠는 승인 동작이 같다.
- 메뉴는 이름·아이콘만 바꾸고 경로는 그대로다. 관리자 화면의 "후원자 관리"(`/admin/payers`)는 다른 화면이라 그대로 두었다.
- 의존성은 린트 도구 하위 패키지 하나만 고정했다(실행 코드와 무관).
- 스키마·마이그레이션 변경 없음.
