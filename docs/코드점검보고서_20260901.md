## HIGH

### H1. 파트너 API GET /charges에서 후원자 전화번호 원문 노출

**파일**: `src/app/api/partner/v1/charges/route.ts` (약 line 90)

GET /api/partner/v1/charges 응답 페이로드에 `payerPhone: decrypt(r.payer.phoneEnc)` 가 포함된다. 이 엔드포인트는 GET 요청이므로 partner-auth.ts 설계상 HMAC 서명 없이 Bearer 토큰만으로 인증된다.

결과: 사회복지기관 API 키 1개가 유출되면 해당 사회복지기관과 거래한 모든 후원자의 전화번호 원문을 limit=500 단위로 페이지네이션하며 대량 추출할 수 있다.

**권고**:
- GET 응답에서 `payerPhone` 원문을 제거하고, `payerPhoneMasked`(마스킹)와 `payerRef`(해시)만 제공한다.
- 전화번호 원문이 반드시 필요한 경우 POST + HMAC 서명 요구 엔드포인트로 분리한다.

### H2. 소셜 로그인 콜백에 state(CSRF) 검증 코드 없음

**파일**: `src/app/api/auth/social/[provider]/callback/route.ts` (전체)

OAuth 시작 라우트(`/api/auth/social/[provider]`)는 `givesign_social_state_<provider>` 쿠키에 state를 저장한다. 그러나 콜백 라우트에서 state 쿠키와 파라미터를 대조하는 코드가 전혀 없다. 주석에 "state 쿠키와 콜백 state 대조 (CSRF 방어)" 항목이 TODO로 나열되어 있으나 미구현 상태다.

현재는 `KAKAO_CLIENT_ID` 등 키가 없어 실제 OAuth 흐름이 막혀 있어 직접 피해는 없지만, OAuth 연동 키를 추가하는 순간 CSRF 공격에 즉각 노출된다.

**권고**: 콜백 라우트에서 반드시 다음을 수행한다.
```typescript
const cookieState = jar.get(`givesign_social_state_${provider}`)?.value;
const paramState = url.searchParams.get('state');
if (!cookieState || !safeEqual(cookieState, paramState ?? '')) {
  return redirect('/login?error=social_csrf');
}
jar.delete(`givesign_social_state_${provider}`);
```

**권고**: 모든 쿠키 secure 판정을 `env.ts`의 `isProd`(또는 `env.baseUrl.startsWith('https')`) 한 곳으로 통일한다.

// src/lib/env.ts 에 추가
export const secureCookie = env.baseUrl.startsWith('https');

### M2. Redis 장애 시 cron 배치 잠금이 무력화됨

**파일**:
- `src/app/api/cron/payout/route.ts:49`
- `src/app/api/cron/cleanup/route.ts:44`

```typescript
const locked = await kv.setnx(LOCK_KEY, ..., LOCK_TTL_SEC).catch(() => true);
if (!locked) return skip;
```

Redis 오류 시 `catch(() => true)` 로 인해 잠금 획득 성공으로 처리되어 배치가 실행된다. Redis가 다운된 상태에서 AWS EventBridge 등이 동시에 여러 번 호출하면 `payout` 배치가 중복 실행된다.

payout 배치는 사회복지기관 이체를 일으키므로 DB 레벨의 멱등키로 이중 지급이 방어되긴 하나, 잠금이 무력화되는 것 자체가 위험 신호다.

**권고**: Redis 실패 시 배치를 skip 처리한다.
```typescript
const locked = await kv.setnx(LOCK_KEY, ..., LOCK_TTL_SEC).catch(() => false); // false = 잠금 미획득
if (!locked) return skip;
```

### M3. 구브랜드 상태명 `BROADCAST_PENDING` / `BROADCASTED` / `PARTIAL_DELIVERY_FAILED` 잔류

**파일**: `src/server/services/charge-flow.ts`, `executePayment` 함수 내

```typescript
if (['PAYMENT_SUCCESS', 'BROADCAST_PENDING', 'BROADCASTED', 'PARTIAL_DELIVERY_FAILED',
     'SETTLEMENT_PENDING', 'SETTLED'].includes(charge.status)) { ... }
```

`BROADCAST_PENDING`, `BROADCASTED`, `PARTIAL_DELIVERY_FAILED`는 도네이도 시절 "방송 노출"에서 비롯된 용어다. 현재 CLAUDE.md에서 "방송 노출 → 충전 반영"으로 개명했으나 Enum 값이 갱신되지 않았다(`src/generated/prisma/enums.ts:119-121` 확인).

Enum 값이 DB에 그대로 저장되어 있으므로 런타임 동작에는 문제가 없지만, CLAUDE.md의 브랜드 원칙에 따라 새 마이그레이션으로 개명해야 한다.

**권고**: 신규 마이그레이션을 추가하여 `BROADCAST_PENDING → REFLECT_PENDING`, `BROADCASTED → REFLECTED`, `PARTIAL_DELIVERY_FAILED → PARTIAL_REFLECT_FAILED` 로 변경한다. (기존 SQL은 수정하지 않는다)

### M4. partner-auth.ts: Redis 장애 시 rate limit 무력화

**파일**: `src/server/services/partner-auth.ts:112`

```typescript
const used = await kv.incr(`partner:rate:${key.id}:${minuteBucket}`, 90).catch(() => 0);
if (used > RATE_LIMIT_PER_MIN) { ... }
```

Redis 오류 시 `catch(() => 0)` 으로 카운터가 0 처리되어 rate limit이 우회된다. Redis 장애 중 악의적 사회복지기관이 초당 수천 건의 요청을 보낼 수 있다.

**권고**: Redis 실패 시 보수적으로 처리한다.
```typescript
const used = await kv.incr(..., 90).catch(() => RATE_LIMIT_PER_MIN + 1);
if (used > RATE_LIMIT_PER_MIN) return fail(429, ...);
```

### M6. `expireStaleConfirmations` N+1 쿼리 패턴

**파일**: `src/server/services/charge-confirm.ts:76-86`

```typescript
const stale = await prisma.secureLink.findMany({ where: { ... } });
for (const s of stale) {
  const d = await prisma.charge.findUnique({ where: { id: s.chargeId! } }); // N번
  await setStatus(s.chargeId, 'PAYMENT_FAILED', ...);                        // N번 × 2
}
```

stale 링크가 N개이면 2N+1 번의 DB 왕복이 발생한다. 배치가 1분마다 실행되고 미확인 건이 누적될수록 실행 시간이 선형 증가하여 LOCK_TTL_SEC(55초) 초과 가능성이 있다.

**권고**: `findMany`에 `include: { charge: { select: { status: true } } }` 를 추가해 조인으로 처리하고, `setStatus` 를 `$transaction` 으로 묶어 배치 업데이트한다.
