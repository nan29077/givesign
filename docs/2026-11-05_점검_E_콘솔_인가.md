## 2. 발견 사항

### [심각도: 높음] 파트너 API 상품 등록이 콘솔의 제한(FEATURE_GOODS·금액 범위·개수·이름 중복·종류 고정)을 모두 우회한다
- 위치: `src/server/services/partner-products.ts:63-167`, `src/app/api/partner/v1/products/route.ts:42-73`, `src/app/api/partner/v1/products/[id]/route.ts:32-58`, `src/app/api/partner/v1/products/bulk/route.ts`
- 내용:
  ```ts
  // partner-products.ts:69-75  kind 를 PHYSICAL 로 받아 그대로 저장
  const kind = String(input.kind).toUpperCase();
  if (!KINDS.includes(kind)) return { ok: false, ... };   // KINDS = ['DIGITAL','PHYSICAL']
  data.kind = kind as ProductKind;
  // :96-101  금액은 0 이상 정수면 통과(기관 범위·한도 정책 미확인)
  if (!Number.isInteger(amount) || amount < 0) ...
  // :17, :155  개수 상한 200 (콘솔은 MAX_CHARGE_PRODUCTS = 12)
  ```
  `featureGoodsEnabled()` 는 `src/app/api/**` 어디에서도 호출되지 않는다(grep 결과 없음). 콘솔 액션 `createChargeProductAction` 은 `studio.ts:799-801` 에서 실물·문서 생성을 거절하고 `effectiveAmountRange` 로 금액 범위를 강제하지만, API 경로에는 같은 규칙이 없다. PATCH(`[id]/route.ts:48`)는 `partial: true` 로 `kind` 변경까지 허용해 콘솔이 금지한 "종류 변경"(`studio.ts:842-843`)이 가능하고, 보관(archivedAt)된 상품도 수정된다.
- 영향: CLAUDE.md "꺼져 있으면 … 실물·문서 생성은 서버 액션에서도 거절" 규칙이 API 로 무력화된다. 운영 키만 있으면 FEATURE_GOODS=false 상태에서도 실물 상품을 만들어 후원페이지에 노출시킬 수 있고(후원 서비스에 "배송 상품"이 등장), 금액 0원·한도 밖 상품이 생겨 결제 단계에서 전건 AMOUNT_RANGE 실패하거나 0원 결제가 시도된다. 종류 변경은 과거 주문의 배송 유무를 뒤집는다.
- 수정 제안: `createPartnerProduct`/`syncPartnerProducts`/PATCH 에서 (1) `!featureGoodsEnabled() && kind !== 'DIGITAL'` 거절, (2) `effectiveAmountRange(merchantId)` 와 같은 범위 검사(콘솔과 함수 공유), (3) `amount <= 0` 거절, (4) PATCH 에서 `kind` 필드 무시 또는 거절·보관 상품 수정 거절, (5) 개수 상한을 `MAX_CHARGE_PRODUCTS` 와 통일하거나 의도적 차이를 문서화.
- 확신도: 확인됨

### [심각도: 높음] 운영 환경에서 시드가 전체 건너뛰어져 약관·전역 수수료/한도 정책·공휴일이 비어 있는 상태로 기동할 수 있다
- 위치: `prisma/seed.ts:13-18`, `src/server/services/settlement.ts:242-254`, `src/server/services/limits.ts:81-106`
- 내용:
  ```ts
  // seed.ts:15-18
  if (isProd) {
    console.log('[seed] 운영 환경에서는 관리자 시드 계정을 생성하지 않습니다.');
    process.exit(0);
  }
  ```
  운영에서는 테스트 계정뿐 아니라 `termsVersion`(seed.ts:44-55), 전역 `chargeLimitPolicy`(63-66), 전역 `feePolicy`(68-72), 공휴일, 시스템 설정까지 아무것도 들어가지 않는다. `package.json` 에 운영용 부트스트랩 스크립트는 없다(`db:seed` 하나). `resolveFeePolicy` 는 정책이 없으면 `null` → 코드 기본값(1.8%/15%)이 조용히 적용되고, 약관 테이블이 비면 후원 확정 화면의 동의 목록이 비게 된다.
- 영향: 운영 첫 배포에서 관리자가 `/admin/fees`, `/admin/terms`, `/admin/holidays` 를 손으로 채우기 전까지 정산은 기본 요율로, 약관 동의는 빈 목록으로 진행된다. `/admin/fees` 화면은 "미설정 · 기본값 적용" 을 띄우지만(page.tsx:81-88) 강제는 아니다.
- 수정 제안: 시드를 "운영에서도 들어가야 하는 기준 데이터(약관·전역 정책·공휴일·SystemSetting)" 와 "로컬 전용 샘플(계정·거래)" 로 분리하고 운영에서는 전자만 실행. 또는 `assertProductionSafety()` 에 "현행 약관·전역 수수료 정책 존재" 점검을 추가.
- 확신도: 확인됨 (운영 배포 절차에 별도 SQL 이 있을 가능성은 배제하지 못함)

### [심각도: 중간] FEATURE_GOODS 가 꺼져도 복제·복원 액션으로 실물/문서 상품이 다시 생성·활성화된다

- 내용:
  ```ts

  const src = await prisma.chargeProduct.findFirst({ where: { id, merchantId, archivedAt: null } });
  ```

  생성 액션(`:799`)만 플래그를 보고, 복제(새 행 생성)·복원(보관 해제)·수정·`toggleChargeProductActiveAction` 은 보지 않는다. 화면(`products/[id]/page.tsx:52`)은 404 지만 서버 액션은 `productId` 만 알면 호출된다(`/studio/products` 목록 소스나 과거 주문 상세에 id 가 남는다).
- 영향: 메시지페이 시절 남아 있던 PHYSICAL/DOCUMENT 상품을 복제·복원·노출해 공개 후원페이지(`charge-select`)에 실물 상품이 나타날 수 있다.

## 3. 확인했으나 문제 없음(참고)

- 모든 `/admin/**`, `/studio/**` 페이지가 레이아웃 외에 자체 `requireAdmin()`/`requireMerchant()` 를 호출한다(`settlement/account/page.tsx` 는 리다이렉트 전용). 레이아웃-페이지 병렬 렌더 문제 없음.
- 관리자 권한 판정은 화이트리스트(`shared.ts:27-28`, `components/admin/constants.ts:66-70`)로 서버·화면이 같은 집합을 쓴다.
- 기관 콘솔 액션은 `merchantId` 를 폼이 아닌 세션에서만 받고, 대상 레코드 조회에 항상 `merchantId` 조건을 건다(IDOR 미발견). 승인 전 기관은 `requireMerchant` 에서 차단.
- 환불은 `requestRefund`(REFUND_REQUESTED 전이)만 가능하고 파트너 API 에 환불 실행 경로가 없다.
- 요율은 `percentRate` 로 퍼센트 입력 → 소수 문자열 저장, 표시는 `ratePercent` 로 ×100. 100배 혼동 지점 없음. 수수료 정책은 `effectiveFrom/To` 로 판정(`resolveFeePolicy`).
- 파트너 API: 키는 HMAC 해시 조회, 서명은 `timingSafeEqual`, 타임스탬프 오차 300초 + 쓰기 요청 nonce(서명) 재사용 차단, 저장소 장애 시 fail-closed(503). 샌드박스는 TEST 키 전용 + 별도 테이블로 운영 데이터와 분리. `/api/dev/outbox` 는 `APP_ENV=local` 외 404 (APP_ENV 미설정은 fail-closed).
- 전화번호·계좌·주민번호는 화면·클라이언트 props 에 마스킹 값만 전달됨을 대시보드·정산·정기후원·결제 상세·관리자 정산 패널에서 확인. 배송지 원문은 열람 액션/CSV 에서만 복호화하고 감사로그를 남긴다.
- `/studio/orders` 는 `orders/layout.tsx` 에서 FEATURE_GOODS 미설정 시 404. 설정 화면의 배송 탭·대시보드 타일도 플래그로 숨김.
- 공개 페이지가 모두 `force-dynamic` 이라 배너·상품 변경 후 `revalidatePath` 누락이 화면 갱신 문제를 만들지 않는다.
