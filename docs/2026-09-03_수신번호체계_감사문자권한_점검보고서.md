## 요약

1. **0505 는 버그가 아니라 현재 설계다.** 2026-08-20 에 1588 체계를 버리고 050 안심번호로 전면 전환했고, 그 이후 등록·수신·표기·시드·테스트 전부가 `050` 을 강제하고 있다. 1688 로 바꾸려면 6개 지점을 함께 바꿔야 한다.
2. **1688-1234-XXXX 는 개발 전에 통신사 확인이 먼저 필요하다.** 15xx/16xx 대표번호는 8자리다. 뒤 4자리(XXXX)를 붙인 12자리를 MO 수신번호로 쓸 수 있는지는 문자중계사가 확장번호를 MO 로 넘겨주느냐에 달려 있다. 여기서 갈리면 개발 범위가 완전히 달라진다.
3. **감사문자를 사회복지기관가 직접 셋팅하는 기능은 이미 있다.** 지시하신 구조(사회복지기관 설정 우선 · 미설정 시 최고관리자 문구)가 그대로 구현되어 동작 중이다. 다만 "최초 문자 · 핀번호 문자는 최고관리자" 부분은 현재와 어긋난다(아래 2-3).

# 1. 문자번호 체계

## 1-1. 지금 왜 0505 로 배정되는가

번호는 자동 발급이 아니라 **최고관리자가 재고에 등록 → 사회복지기관에 배정**하는 수동 구조다.
등록 단계에서 `050` 이 아니면 아예 저장되지 않는다.

| 지점 | 파일 | 내용 |
|---|---|---|
| 관리자 등록 검증 | `src/app/actions/admin/transactions.ts:20,30` | `/^050[0-9]{7,10}$/` — 050 아니면 등록 거부 |
| MO 수신 어댑터 | `src/server/adapters/mo/mtonet.ts:136` | 050 아닌 수신번호는 **라우팅 사고로 간주해 즉시 거절** |
| 결제페이지 번호 표기 | `src/app/c/[code]/page.tsx:44-48` | 0505-xxxx-xxxx 포맷. (1xxx-xxxx 8자리 분기는 이미 있음) |
| 시드 데이터 | `prisma/seed.ts:104-105, 473-475` | `05051001001`, `05059000000`. 시드 v5 가 옛 1588 번호를 050 으로 덮어씀 |
| 관리자 화면 안내 | `src/app/admin/mo-numbers/page.tsx:94,95,124` | placeholder `05051234567` |
| 테스트 | `tests/adapters.test.ts`, `tests/charge-flow.test.ts`, `tests/helpers.ts` | 050 기대값 고정 |

즉 사회복지기관 콘솔에 0505 가 보이는 것은 **정상 동작**이고, 바꾸려면 정책 변경이다.

## 1-2. 개발 전에 확정해야 할 것 (★ 지시 필요)

`1688-1234-XXXX` 는 12자리다. 국내 지능망 대표번호(15xx/16xx/18xx)는 **8자리**이고, 뒤에 붙는 확장번호는 원래 음성 ARS 내선 개념이다. 문자(MO)에서도 확장번호까지 구분해 넘겨주는지가 관건이다.

**경우 A — 중계사가 12자리를 그대로 넘겨준다**
: 사회복지기관마다 고유번호를 주는 현재 방식(DEDICATED)을 그대로 유지. 정규식과 표기 포맷만 넓히면 된다. 작업량 작음.

**경우 B — 중계사가 대표번호 8자리(1688-1234)만 넘겨준다**
: 뒤 4자리로는 사회복지기관을 구분할 수 없다. 이때 XXXX 를 화면에만 표시하면 **모든 결제가 한 사회복지기관으로 몰리는 사고**가 난다. 이 경우에는 이미 구현되어 있는 **대표번호 공유 + 키워드 방식(SHARED_PREFIX)** 을 써야 한다 — 후원자가 문자 맨 앞에 사회복지기관 키워드를 붙여 보내는 방식이고, 코드·시드·라우팅이 이미 다 있다.

> 중계사(MTONET)에 물어볼 문장: "1688-XXXX 대표번호로 들어온 MO 를 URL 로 푸시할 때, `to`(수신번호) 필드에 확장번호 4자리까지 포함된 12자리가 들어옵니까, 아니면 대표번호 8자리만 들어옵니까?"

같이 확정할 것 두 가지:
- **MT 발신번호 정책** — 회신 문자를 1688 번호로 보낼지, 별도 발신번호를 쓸지. 현재 기본값은 아직 옛 번호 `15880000` (`src/lib/env.ts:149,154`).
- **발신번호 사전등록** — 1688 번호로 MT 를 보내려면 전기통신사업법상 사전등록이 필요하다. 명의·서류 준비 주체 확인 필요.

## 1-3. 1688 확정 시 수정 대상 (지시 주시면 이대로 진행)

1. `transactions.ts` 등록 정규식 — `/^(050|1[5-8]\d\d)[0-9]{4,8}$/` 형태로 확장(과도기에는 0505 도 계속 허용 권장)
2. `mtonet.ts` 수신 검증 — 같은 규칙으로 통일. **여기를 안 고치면 1688 로 들어온 문자가 전부 거절된다**
3. `c/[code]/page.tsx` 번호 표기 포맷에 1688-1234-XXXX(4-4-4) 분기 추가
4. `seed.ts` 시드 번호 교체 + 시드 v6 로 기존 미리보기 DB 의 0505 번호 갱신
5. 관리자 화면 placeholder·검색 안내 문구
6. 테스트 4개 파일 기대값 + `env.ts` 기본 발신번호
7. 운영 DB 마이그레이션 — 이미 배정된 0505 번호를 어떻게 할지(병행 운영 / 일괄 교체) 별도 결정 필요

**주의:** 번호를 바꾸면 후원자가 기존에 저장해 둔 0505 번호로 보낸 문자는 `UNKNOWN_ROUTE` 로 실패한다. 일정 기간 두 번호를 함께 살려 두는 편이 안전하다.

## 2-1. 지시하신 구조는 이미 구현되어 있다

**최고관리자 경로**

: 저장 위치 `MtMessageTemplate` 테이블. 재배포 없이 문구 교체 가능

**우선순위 (`src/server/services/mt-templates.ts:228-247`, `:640-642`)**

```
사회복지기관이 설정한 문구  >  최고관리자가 설정한 문구  >  코드 기본 문구
```

사회복지기관이 직접 저장하면 템플릿 출력에 `vars` 를 넘기지 않고, `applyMtTemplateOverride` 는 `vars` 가 없으면 관리자 문구를 덮어쓰지 않는다. 즉 **사회복지기관이 설정 안 하면 최고관리자 문구가 나간다** — 지시하신 그대로다.

발송 경로 두 곳 모두 이 규칙을 탄다: 정상 결제 완료(`charge-flow.ts:1239`), 결과 미확인 건 사후 확정(`payment-reconcile.ts:213`).

**사회복지기관 문구에 걸린 안전장치**
: 200자 제한 · 치환자 `{후원자} {사회복지기관} {금액} {메시지} {누적}` 5개만 허용 · 링크(http, www)·전화번호·계좌번호 저장 차단 · 금칙어 필터 · `[기브싸인]` 발신주체 표기 강제 부착.

## 2-3. 지시 내용과 현재 구조가 어긋나는 3가지 (★ 지시 필요)

**① 최초 문자·핀번호 문자는 최고관리자도 못 고친다.**
헥토 계좌/빌링키 등록 안내와 PIN 입력 요청은 본문에 **보안링크**가 들어간다. 링크가 빠지거나 잘리면 결제 흐름 자체가 끊기므로, 화면에서는 읽기 전용으로만 보여주고 코드에서만 관리하도록 막아 두었다(`MT_TEMPLATE_META` 의 `editable:false`).
→ 지시하신 대로 최고관리자가 셋팅하게 하려면, **MO 안내 문자에 이미 쓰고 있는 방식**(사회복지기관은 앞 문구만 쓰고, 링크와 "아직 결제되지 않았습니다" 고지는 시스템이 강제로 붙임)을 이 두 문자에도 적용하면 된다. 안전하게 열 수 있다. **여는 게 맞는지 지시 필요.**

**② MO 안내 문자가 권한이 뒤집혀 있다.**
"문자 보내면 곧바로 나가는 첫 안내 문자"(SELECT_AMOUNT)는 지금 **사회복지기관은 고칠 수 있는데 최고관리자는 못 고친다.** 지시 내용("최초 문자는 최고관리자")과 정확히 반대다.
→ (가) 사회복지기관 설정을 회수해 최고관리자 전용으로 되돌릴지, (나) 감사문자처럼 최고관리자 기본값 + 사회복지기관 우선 구조로 맞출지 **지시 필요.** (나)를 권한다 — 이미 사회복지기관이 쓰고 있는 기능을 뺏지 않으면서 최고관리자가 기본값을 쥘 수 있다.

**③ 최고관리자가 "어느 사회복지기관이 자기 문구를 쓰는지" 볼 수 없다.**
관리자 화면 어디에도 `thanksMtMessage` 가 노출되지 않는다. 관리자가 감사문자 문구를 바꿔도 자체 설정한 사회복지기관에는 반영되지 않는데, 그 사실을 알 방법이 없다.
→ `/admin/mt-templates` 에 "자체 문구 사용 사회복지기관 N곳" 표시와 목록을 붙이는 것을 권한다. 작업량 작음.

## 2-4. 같이 잡을 부수 결함

- `prisma/schema.prisma:557-558` — 주석의 치환자가 옛 용어 `{후원자} {사회복지기관}` 로 남아 있다. 실제 동작 치환자는 `{후원자} {사회복지기관}` 이다. 그대로 믿고 쓰면 치환이 안 된다.

## [2026-09-03 추가] 사용자 확정 사항

- **050 은 쓰지 않는다. 1688 번호로 전면 전환한다.**
- 형식은 `1688-XXXX-XXXX`(12자리)이고, **뒤 4자리는 기브싸인가 사회복지기관별로 임의 부여**한다.
- 따라서 위 1-2 의 **경우 A** 로 확정 — 사회복지기관마다 고유 전용번호(DEDICATED)를 주는 현재 방식 유지. 대표번호+키워드(SHARED_PREFIX)로 갈 필요 없음.
- **기존 0505 번호는 병행 운영하지 않는다. 전환 시 같이 끊는다.** → 정규식에 050 을 남기지 말 것. 다만 옛 번호로 들어온 문자는 `UNKNOWN_ROUTE` 로 실패하므로, 그 응답에 새 번호를 안내하는 처리를 함께 검토한다.
- 번호 구조는 `1688 - AAAA - BBBB` (12자리). `AAAA` 는 기브싸인 대표번호 뒤 4자리로 **아직 미정**(보고서의 1234 는 예시일 뿐 확정값 아님), `BBBB` 는 사회복지기관별로 기브싸인가 부여한다. `AAAA` 가 확정되기 전에는 코드에 상수로 박지 말고 환경변수/관리자 등록값으로 둔다.
- 개발은 착수하지 않는다. 사용자가 별도로 지시한다.
- 남은 미결: 4번(MT 발신번호), 5번·6번(문자 편집 권한).
