## 2. 높음

### H-1. 의존성 보안 취약점 (치명 1 · 높음 8)
- `next@16.3.1` 에 **치명** 등급 공지(윈도우 호스팅 서버의 비인증 원격 코드 실행, 이미지 최적화 API RCE 등). PC(윈도우)에서 서버를 띄우는 운영 방식과 직접 맞닿는다. 그 밖에 `prisma`(하위 `@prisma/config`·`mysql2`·`fast-uri`), `zod`(메모리 고갈), `sharp`(libheif·librsvg), `source-map-js` 높음.
- **조치**: `next`·`eslint-config-next` 16.4.6, `prisma`·`@prisma/client`·`@prisma/adapter-pg` 7.10.1, `zod` 4.6.7, `vitest` 4.1.12, 하위 `sharp` 0.35.5, `package.json` `overrides` 로 `source-map-js` ^1.2.2 · `fast-uri` ^3.1.9. 운영 의존성 0건.
- 남은 것: 개발 전용 린트 도구(typescript-eslint 의 minimatch) **중간 8건** — eslint 메이저 업그레이드가 필요해 남김(운영 영향 없음, 6절 D-4).

### H-2. 한글 글꼴이 없는 서버에서 카드뉴스·숏폼·SNS 게시 이미지의 한글이 사라짐 (법정 표시 포함)
- 장면 SVG → PNG/MP4 변환(sharp·librsvg)은 **서버에 설치된 글꼴만** 찾는다. 장면 SVG 글꼴 목록(`'Malgun Gothic', Pretendard, 'Noto Sans KR'`)은 운영 리눅스 이미지에 없다.
- 한글 글꼴이 없는 환경을 흉내 내 렌더한 결과: 제목·기관명이 **아예 안 보이고**, 하단 "AI 생성 콘텐츠 · 기부금품 모집등록번호" 표시가 □ 로 깨짐. SNS 에 그대로 게시되면 모집등록번호 표시 의무도 지키지 못한다.
- **조치**: `src/server/adapters/content/fonts.ts` `ensureBundledFonts()` — 저장소에 이미 있는 `assets/fonts`(Noto Sans CJK KR, OFL)를 기존 fontconfig 설정에 더한 설정 파일을 만들어 가리킨다. sharp 를 부르는 두 곳(`content/video.ts`·`sns/media.ts`)이 첫 렌더 전에 호출. 장면 SVG 글꼴 목록에 번들 글꼴 이름 추가(`SCENE_FONT_FAMILY`). 같은 환경에서 다시 렌더해 한글·법정 표시가 정상인 것을 확인. 끄기 `GIVESIGN_BUNDLED_FONTS=off`.

### H-3. 배포 가이드대로 하면 운영 서버가 뜨지 않음
- `next.config.ts` 의 빌드 폴더가 `distDir: '.givesign-next'` 인데 `docs/AWS-배포-가이드.md` 와 설정 주석은 `node .next/standalone/server.js` 로 안내. 또 standalone 출력에 필요한 정적 파일(`static`)·`public` 복사 단계가 없음.
- **조치**: 가이드 4절을 `.givesign-next/standalone/server.js` + 정적 파일·public **내용** 복사(폴더째 복사하면 `public/public` 이 생김)로 고치고, 실제 standalone 빌드 → 가이드 절차 → 기동해 메인·후원페이지·로그인·정적 JS 200 확인. 설정 주석도 수정.

### H-4. standalone 배포 출력에 로컬 비공개 저장소가 통째로 실림
- `uploads.ts` 가 `process.cwd()/var` 를 동적으로 읽어 빌드 파일 추적이 `var/uploads`·**`var/private`**(서명 문서·암호화 스냅샷·기관 업로드 글꼴, 점검 환경에서 23MB·91개 파일)를 standalone 에 복사. PC 에서 운영 이미지를 빌드하면 비공개 문서가 이미지 안에 들어간다. 빌드 컨텍스트의 `.env` 도 Next 가 standalone 에 복사한다.
- **조치**: `next.config.ts` `outputFileTracingExcludes` 로 `./var/**` 제외(`/**/*` 글롭이 루트 `/` 와 맞지 않아 루트 키를 따로 둠 — 재빌드로 제외 확인). `.dockerignore` 추가(`.env`·`var`·`node_modules`·빌드 산출물). 가이드에 안내.

## 3. 중간

### M-1. 카드뉴스 작성 안내 문구가 그대로 저장·공개됨
- 캠페인 편집의 "스토리형 6장 만들기"·템플릿은 빈 칸에 "…적어 주세요" 같은 안내를 넣는다. 저장 검증이 없어 그대로 저장하면 공개 후원페이지에 안내 문구가 캠페인 본문처럼 나간다. (기존 카드가 있으면 버튼이 잠겨 덮어쓰기는 일어나지 않음 — 확인)
- **조치**: 저장 검증(`campaignSchema.cardNews` = `campaignCardsSaveSchema`, `hasCardGuidance`)이 "N번째 장에 작성 안내 문구가 남아 있습니다"로 막는다. 읽기(`readCampaignCards`)는 그대로라 이미 저장된 카드가 화면에서 사라지지 않는다. 편집기는 해당 카드에 경고를 띄우고 안내문도 고침. 마지막 장의 "참여해 주세요"는 막지 않음.

### M-2. 내려받기 버튼이 화면을 열 때마다 CSV 내보내기를 요청
- `LinkButton`(next/link)으로 건 `/api/bazaar/export` 버튼 6곳(기관 바자회 홈·판매·정산, 관리자 판매 입력·기부자 대장·상품)이 화면에 보이는 순간 미리 불러오기(prefetch)로 내보내기를 요청 — 404 가 나거나 응답 없이 매달려 `/studio/bazaar` 가 계속 로딩 상태.
- **조치**: `LinkButton` 이 `/api/…` 경로는 일반 `<a>` 로 그린다(전역 — 앞으로 생길 내려받기 버튼도 같은 규칙). 재점검에서 요청·매달림 없음 확인.

## 5. 확인했지만 문제 없음

- **관리자 서버 액션**: 전부 `run()`(쓰기 권한 화이트리스트)을 통과, 금전·정책 변경은 `assertMoneyAdmin`/`requireFinanceAdmin`, 관리자 권한 변경·관리자 추가·약관 등록·관계 안내 법무 스위치·바자회 스위치는 최고관리자만.
- **기관·후원자 액션**: 공통 래퍼(`withMerchant`·`requireGiver`·본인확인 증표·토큰)로 보호.
- **비로그인 경로**: 서명 PDF·묶음 PDF는 본인확인 쿠키 증표, 발급 문서 링크는 토큰 해시 + 만료·기관 정지·탈퇴 확인, 미디어는 128비트 파일명 + nosniff·sandbox CSP, 개발용 발송함은 로컬 외 404.
- **외부 호출**: 배치는 Bearer 상수 시간 비교(운영에서 비밀 미설정이면 거절), PIN 콜백은 IP 허용목록 + 공유 비밀, MO 웹훅은 서명 검증 전 기록 없음·IP 속도 제한·본문 상한.
- **보안 헤더**: 클릭재킹 차단(frame-ancestors none), nosniff, Permissions-Policy, HTTPS 일 때 HSTS.
- **화면**: 공개·콘솔·마이페이지 전 화면 HTTP 200, 가로 넘침 0, 옛 용어("메시지페이·가맹점") 노출 0. "충전"은 전자문서 선불 요금 화면의 맞는 용어. 점검 중 보인 하이드레이션 경고는 점검 도구(스크린샷 커서 숨김 스타일)가 만든 것으로 확인.
