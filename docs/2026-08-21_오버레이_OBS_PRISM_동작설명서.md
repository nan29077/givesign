# 방송 오버레이 — OBS · PRISM 에서 후원이 어떻게 뜨는가

- 일자: 2026-08-21
- 대상: `방송·오버레이` 메뉴 (`/studio/overlay`)
- 결론: **구조는 제대로 잡혀 있고 실행 검증도 통과했습니다.** 다만 오픈 전에 손봐야 할 항목 3가지가 있습니다(6장).

---

## 1. 한 줄 요약

사회복지기관가 발급받은 **브라우저 소스 URL** 을 OBS/PRISM 에 넣어두면, 그 페이지가 서버와 연결을 계속 열어두고 있다가 **후원 결제가 성공하는 순간 서버가 밀어주는 신호**를 받아 화면에 감사 애니메이션을 띄웁니다. 방송 프로그램은 그 페이지를 그냥 웹페이지처럼 화면에 겹쳐 그릴 뿐, 후원 처리에는 관여하지 않습니다.

---

## 2. 전체 흐름

```
후원자가 문자 발송 (또는 PC 웹 후원)
        │
        ▼
  MO 수신 → 사회복지기관 라우팅 → 한도·금칙어 검사
        │
        ▼
  내통장결제 승인   ←── 여기서 실패하면 오버레이로 아무것도 안 나갑니다
        │
        ├─ 결제 승인 + 정산 원장 3분개 (같은 트랜잭션)
        │
        ▼
  dispatchBroadcast(donationId)
        │
        ├──▶ sendOverlay()  ──▶ publishOverlayEvent()
        │                          │
        │                          ├─ 같은 서버 프로세스의 구독자에게 즉시 전달
        │                          └─ Redis pub/sub 으로 다른 인스턴스에도 전파
        │                                    │
        │                                    ▼
        │                     GET /api/overlay/{creatorId}/stream?token=...
        │                     (SSE, 계속 열려 있는 연결)
        │                                    │
        │                                    ▼
        │                     OBS · PRISM 브라우저 소스에 뜬 오버레이 페이지
        │                     → 대기열에 넣고 한 건씩 순차 재생
        │
        └──▶ sendYouTube()  ──▶ 라이브 채팅에 후원 메시지 등록
```

핵심은 **"결제 성공 이후에만 호출된다"** 는 원칙입니다. 결제 실패·한도 차단·금칙어 차단 건은 오버레이에 절대 나가지 않습니다. 실행 테스트로 확인했습니다(미등록 후원자의 문자 → 오버레이 이벤트 0건).

---

## 3. 사회복지기관가 실제로 하는 일

1. `/studio/overlay` → **브라우저 소스 URL 발급**
   → `https://<도메인>/overlay/<사회복지기관ID>?token=<발급토큰>` 형태의 주소가 나옵니다.
   토큰은 **발급 직후 한 번만** 화면에 보이고, 서버에는 해시로만 저장됩니다.

2. **OBS**: 소스 추가 → `브라우저` → URL 칸에 붙여넣기 → 너비 1920 / 높이 1080
   **PRISM**: 소스 추가 → `웹페이지(브라우저)` → 동일

3. 이후 방송 중 후원이 들어오면 자동으로 뜹니다. 방송 시작 전 `테스트 알림 보내기` 로 미리 확인할 수 있습니다.

---

## 4. 왜 SSE(Server-Sent Events) 인가

오버레이는 **서버 → 브라우저 한 방향**으로만 데이터가 흐르면 됩니다(후원이 들어왔다는 신호). 이런 경우 WebSocket 보다 SSE 가 유리합니다.

- 일반 HTTP 연결이라 방송용 PC의 방화벽·프록시를 잘 통과합니다
- 연결이 끊기면 브라우저가 **자동으로 재연결**합니다 (오버레이 클라이언트에 지수 백오프 재시도까지 구현돼 있고 최대 30초 간격)
- 20초마다 하트비트(`: ping`)를 보내 중간 프록시가 유휴 연결을 끊는 것을 막습니다
- `X-Accel-Buffering: no` 헤더로 nginx/ALB 버퍼링을 끕니다 — 이게 없으면 이벤트가 버퍼에 갇혀 몇 초씩 늦게 뜹니다

방송 중 인터넷이 잠깐 끊겨도 복구되면 알아서 다시 붙습니다. 다만 **끊겨 있던 동안 들어온 후원은 다시 재생되지 않습니다**(6장 참조).

## 5. 오버레이에 실려 나가는 내용

| 항목 | 설명 |
|---|---|
| `donorName` | 후원자 표시명. `익명 처리` 설정이거나 후원자가 익명을 선택하면 **"익명의 후원자"** |
| `amount` | 후원 금액. `금액 표시` 를 끄면 화면에서 감춥니다 |
| `message` | 후원 메시지. `메시지 표시` 를 끄면 **빈 값으로 나갑니다** (서버에서 비웁니다 — 화면에서만 숨기는 게 아닙니다) |
| `sticker` | 스티커 세트 |
| `tts` | 음성 읽기 (설정 금액 이상일 때만) |
| `durationMs` | 표시 시간 (기본 7초) |
| `isTest` | 테스트 알림 여부 |

메시지에는 이미 **금칙어 필터와 개인정보 자동 마스킹**이 적용된 뒤의 내용이 들어갑니다. 방송에 전화번호·계좌번호가 그대로 뜨는 일은 없습니다.

여러 건이 동시에 들어와도 **대기열에 넣고 한 건씩 순차 재생**하며, TTS 가 있으면 음성이 끝날 때까지 다음 건으로 넘어가지 않습니다.

## 6. 점검 결과

### 정상 확인 (실행 검증 완료)

| 항목 | 결과 |
|---|---|
| 결제 성공 후원이 오버레이 이벤트로 발행되는가 | ✅ |
| 페이로드에 금액·메시지·표시시간이 담기는가 | ✅ |
| 익명 설정 시 이름이 감춰지는가 | ✅ ("익명의 후원자") |
| 메시지 숨김 설정 시 서버에서 비우는가 | ✅ (빈 문자열) |
| 결제되지 않은 후원이 새어나가지 않는가 | ✅ (이벤트 0건) |
| 잘못된 토큰으로 SSE 접근 차단 | ✅ (401) |
| Redis 장애 시에도 같은 프로세스 오버레이는 동작 | ✅ (로컬 전달이 기본, Redis 는 추가 전파용) |
| 다중 인스턴스 전파 | ✅ (Redis pub/sub + 중복 재생 방지) |
| 유튜브 송출 실패가 결제를 뒤집지 않는가 | ✅ (예외 격리 완료) |

### 오픈 전 손봐야 할 항목

**O-1 (높음) 재연결 중 놓친 후원은 다시 뜨지 않습니다.**
SSE 는 `Last-Event-ID` 로 놓친 이벤트를 재전송하는 표준 기능이 있는데, 현재는 이벤트에 `id:` 필드를 붙이지 않아 이 기능이 꺼져 있습니다. 방송 중 인터넷이 10초 끊기면 그 사이 후원은 화면에 영영 안 뜹니다(정산·유튜브 댓글은 정상). 후원자는 돈을 냈는데 화면에 안 나오니 항의가 들어옵니다.
→ 조치: 이벤트에 `id:` 를 붙이고 최근 N건을 메모리/Redis 에 보관해 재연결 시 재전송.

**O-2 (중간) 오버레이 페이지가 사회복지기관ID를 URL 에 그대로 노출합니다.**
`/overlay/<사회복지기관ID>?token=...` 구조라 방송 화면에 주소창이 잡히면 내부 식별자가 노출됩니다. 토큰이 있어야 동작하므로 당장 뚫리는 건 아니지만, 불투명한 단일 토큰 경로(`/overlay/o/<토큰>`)로 바꾸는 편이 안전합니다.

**O-3 (중간) SSE 연결 수 제한이 없습니다.**
한 사회복지기관가 URL 을 여러 곳에 열어두거나, 토큰이 유출돼 다수가 접속하면 연결이 무제한으로 쌓입니다. 서버 인스턴스당 동시 연결 상한과 사회복지기관당 상한이 필요합니다.

## 7. 자주 나올 질문

**Q. 방송을 껐다 켜면 다시 연결되나요?**
네. 브라우저 소스가 다시 로드되면서 SSE 가 새로 붙습니다. URL 은 그대로 두면 됩니다.

**Q. URL 을 재발급하면 어떻게 되나요?**
기존 URL 이 **즉시 무효화**됩니다. OBS/PRISM 에 등록된 브라우저 소스를 새 URL 로 바꿔야 후원이 다시 뜹니다.

**Q. 유튜브 채팅에는 올라갔는데 오버레이에 안 떴습니다.**
두 경로는 독립적으로 처리되고 결과도 따로 기록됩니다. 후원 상세에서 `overlay=false youtube=true` 처럼 어느 쪽이 실패했는지 확인할 수 있고, 후원 상태는 `일부 송출실패` 로 남습니다. 이 경우 결제와 정산은 정상입니다.

**Q. PRISM 에서도 OBS 와 똑같이 동작하나요?**
네. 둘 다 내부적으로 Chromium 브라우저를 띄워 웹페이지를 렌더링하는 방식이라 동작이 같습니다. 권장 해상도(1920×1080)만 맞춰주면 됩니다.
